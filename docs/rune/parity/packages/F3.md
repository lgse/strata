## Plan

The package's agent planned it this way after its survey (2026-11-13), approved by the
coordinator with its rulings that day:

1. **`Browser` against the view** (`contract`, the full gate). The fuzz driver asks the Rune
   target for its invariants after every step at rest, with a step of the runner's own,
   `{"invariants":{}}`, answered through `Backend::command`; the GTK target answers that it is
   not supported. The application checks the browser's columns, active column, listings,
   cursor, selection, Shift anchor and load cursor against what the shown view holds, read
   through a read-only `Probe` accessor of each view (`presented`), and the snapshot's panes
   against the view. A broken invariant is a finding, like a GLib warning: no map or mask
   entry covers it. Before the pull request opens, every merged alphabet is run on Rune, each
   class of failure is triaged and filed, and its sequences parked, so the smoke tiers stay
   green the day it merges.
2. **Fixes** of the Rune classes found, one pull request each.
3. **The keyboard's invariants and the stream's** (`contract`, one full gate): the holds a part
   reports against the surfaces open, the focus owner in the tree, a hidden view that never
   acts (#2343), and, in the runner, an Undo followed by a Redo restoring the tree.
4. **The closing**, this file `done`.

Not planned, by the coordinator's ruling: the invariants at the end of every Rune scenario
run of the parity set. It is an option to revisit once the first pull request shows the
invariants clean and cheap.

## What dependents must know

- **Every Rune replay is now held to the invariants** (`docs/testing.md`, "Invariants"): a
  smoke tier with `--target rune` or `gtk,rune` fails on a broken one, with a `FINDING` line,
  as on a GLib warning. A new class is a finding: file it, park its sequences, and tell F3.
- **A view gives the QA probe `presented`**, what it holds of the browser's columns,
  borrowed and never changed (`crate::handover::Presented`). A new view fills it.
