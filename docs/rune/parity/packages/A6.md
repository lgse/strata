## Notes from other packages

From [A8](A8.md) (2026-11-13): **Escape from outside the files** (finding
[#2411](https://github.com/lgse/strata/issues/2411), met by A8's `views` alphabet and parked).
With the keyboard on a header button, such as the Appearance button after its popover closes,
GTK's Escape clears the active column's selection, or closes the preview first: the window's
`dismissal` stage (`src/ui/window/keyboard/items.rs`), for any Escape outside text. On Rune
only the view's own keys clear a selection, while it has the keyboard, and nothing answers
Escape at `Stage::Dismissal`. Its sibling, finding
[#2426](https://github.com/lgse/strata/issues/2426): with nothing selected, GTK's Escape in the
files goes on to the browser's `escape()` (`directory_enter_or_escape`), which closes the
deepest column, and Rune's does not. Once they are answered, drop the sequences' lines from
`tests/qa/fuzz/corpus/views/parked` and replay them with
`./scripts/qa-fuzz.sh replay --parked --alphabet views --target gtk,rune`.

From [B2](B2.md) (2026-11-12), a question for the owner that this package meets: **which
conflicts Rune's keyboard settings report.** `src/ui/keys/conflicts.rs` stays in `src/ui`
when the key catalog moves, because its tables describe GTK (the keys `gtk::Text` binds,
those GTK's list views reserve, the file chooser's mnemonics, GDK's consumed Shift). So the
Rune side gets the catalog, the keymap and the labels, and no conflict check. Open: whether
Rune reports GTK's conflicts or its own, and what it says of a key Rune's host never
delivers ([`owner.md`](../owner.md#a6-and-a18-keyboard-settings)).

From [F2](F2.md) (2026-11-13), the Columns fuzz pilot: **an "Open" row GTK does not show**

From [B3](B3.md) (2026-11-12), a `contract` change to `menus.rs`, this package's file:
**one opener for every view.** `menus::open(app, Request { depth, entry, anchor }, tx)` opens
the menu of a row of the shown view, or of a column's folder when there is no entry. It was
the Columns view's own code (`entry_menu` and `folder_menu` in `columns/intents.rs`), moved
so that the Icons and List views and the Menu key open the same menu: it ends an open
rename, decides what the menu acts on (GTK's `context_entries`: the selection when the
entry is in it, else the entry alone), and builds the folder's menu from the browser. The
menu part now reads "Type to search" from the saved settings itself, for the hints it hides.
`Menu::show` and the `Opening` it takes are private to the file. The rows, their order and
what a chosen row does are unchanged.

From [B3](B3.md) (2026-11-12, [#2214](https://github.com/lgse/strata/pull/2214)), a second `contract` change to `menus.rs`: **the
menu part says it has the keyboard.** `Menu::keyboard` answers `Holds::Menu` while a menu is
open, so the window's commands wait under it as under GTK's popover, and refresh, a window
action, still runs. Since [#2210](https://github.com/lgse/strata/pull/2210) `menus::chosen` runs a row's command from the registry
by the row's id, and `Wired` and `Row::wired` are gone. A dialog or a palette this package
mounts answers `Holds::Modal { field }` in its own `Part::keyboard`, `field` true while a
text field of the layer has the keyboard ([B3's file](B3.md#what-dependents-must-know)).
