## Notes from other packages

From [B1](B1.md):

- **The window's key table.** `shell::on_key` in `crates/strata-app/src/shell.rs` matches
  `WINDOW_KEYS` and skips it while a part's `Part::holds_keyboard` is true; a slot gives a
  part no keys of its own. B3 replaces the table and the body of `on_key` with the command
  registry. A per-part hook goes in `slots::Part`, mirrored in `slots::registry::Entry` and
  `Entry::of`, and called over `Registry::active()`. Until B3 lands no area package adds to
  either, and a run that needs a window chord (Ctrl+T for [A4](A4.md), Ctrl+L for
  [A5](A5.md), the sidebar's key for [A3](A3.md)) stays `pending` on B3.
- **The header's five buttons**, built inert by `shell::bar`, are wired through B3's
  commands, so B3 gives them a seam: what each does comes from the registry, not from five
  packages editing one function. Toggle sidebar (`header-sidebar-toggle`, [A3](A3.md)), New
  tab (`header-new-tab`, [A4](A4.md)), Search (`header-search`, [A10](A10.md)), Appearance
  (`header-appearance`, [A8](A8.md)), Settings (`header-settings`, [A18](A18.md)). The GTK
  window moves New tab and Close into the tab strip when there is more than one tab, which a
  fixed bar cannot do: the seam allows for it, and A4 decides how.
- What a chosen menu row does is decided once in `menus::chosen`; B3's registry replaces
  that match.

From [B2](B2.md):

- **The seam for a press.** B3 builds a normalized `KeyPress` from parts with
  `KeyPress::from_parts`, from what Rune delivers; it never fakes a GDK event. Every builder
  of a press passes a conformance corpus in the shared crate, taken from GTK's layout tests
  (`src/ui/keys/tests/digits.rs`, `letters.rs`, `modifiers.rs`).
- **One reading of the US table** for a press with no physical origin (the QA target, a
  headless test). There are two copies, `src/ui/keys.rs` and
  `crates/strata-app/src/qa/keys.rs`. B2 puts the one implementation in the shared crate;
  the copy in `strata-app` becomes the shared one here or in [H3](H3.md), and nobody writes
  a third.
- **Where the two interfaces would disagree**, measured against Rune at the pinned
  `2a44156`. Each needs a ruling as a deviation, an upstream packet entry with a
  workaround, or a shim; they do not block the move, and they stay this package's and the
  owner's ([`owner.md`](../owner.md#b3-commands-and-key-dispatch)):
  1. A non-Latin layout with a non-US Latin layout also configured: GTK reads the key
     through the other layout, Rune's window host has already put the US key in its place.
     Undo and Redo trade places on QWERTZ.
  2. The digit row above level 1, with AltGr: GTK counts only a digit the key types; Rune
     gives the position and no level. Reaches the tab-number and digit-step keys.
  3. The keypad decimal and separator: GTK does not fold them onto `.` and `,`; Rune does.
     Reaches hidden files (Ctrl+.), Settings (Ctrl+,) and 10xer's Sort trigger.
  4. Every press in the QA target: no physical key and no base on Rune until
     anomalyco/rune#657 lands, so the gate measures another branch of the builder than a
     window uses.
  5. Keys Rune's host never delivers (dead keys, Compose, Caps Lock, AltGr, media keys, F25
     to F35): a user's binding to one loads, gets a label and never fires.
  6. A modifier's own press: GDK reports the state before the event, Rune after it.
  7. Character to keysym: a layout delivers a keysym, Rune a character, and no one choice
     returns the layout's keysym for every character. B2 makes `typed` a character and
     fixes one keysym per printable character.

  The table with the shipped keys each case reaches is in B2's comment on the archived
  issue of 2026-11-12.

From [B2](B2.md), with the catalog's move ([#2195](https://github.com/lgse/strata/pull/2195)):

- **What is there:** `strata_desktop::keys` has `Key`, `Modifiers`, the catalog
  (`keys::bindings`), `registry()`, `Keymap`, `KeyPress` with `from_parts`, `rewrite` and
  the labels. `docs/rune/shared-state.md`, "The key catalog", describes it.
- **Nothing that asks about a key runs on the Rune side until a backend is installed.**
  `KeyPress::from_parts`, `normalize`, a label, `Binding::parse` and `accelerator`, and
  `Keymap`'s reading of saved entries each ask the key library, and panic, saying so,
  when none is installed. Safe today: the key constants, `Binding`'s constructors,
  `registry()`, a `Command`'s id and defaults, and `Keymap::defaults()`. B2's next pull
  request is a table backend over the declared constants, installed by `strata-app`;
  B3 starts when it merges.
- **Saved keymaps on the Rune side wait for the accelerator reader** (B2's remaining
  work, step 3): the table backend reads and writes no accelerator string, so until then
  the Rune side resolves through `Keymap::defaults()`.
- **`keys::set_active` is one slot for the thread, holding a weak reference.** Whoever
  registers keeps the source alive; when it is dropped the catalog reads the shipped
  defaults again. `Fixed` holds the three answers as values, so a change of settings
  means registering a new one, or B3 implements `Active` on something it already keeps.
- **`from_parts` decides whether the press is a modifier from the shared list of
  modifier keys alone.** GTK's reader also takes GDK's word for it; an interface that
  knows more gives the modifier key as `Typed::Key`.
- **`Typed::Character` goes through `Key::from_char`,** so the key a character stands
  for is the backend's answer. A named key, a modifier or a keypad key is given as
  `Typed::Key`: GDK reports a keypad key as itself, not as the character it types.
- **A constant for a named key Rune delivers goes in
  `crates/strata-desktop/src/keys/key_constants.rs`,** whether or not the catalog binds
  the key: X's keysym name, the value from `xkbcommon-keysyms.h`. While GTK exists each
  must be a name GDK reads, which a GTK-lane test checks; a key GDK does not name is
  raised in this file and in [`owner.md`](../owner.md) before it is added.
- **Which bindings never fire** is an answer the interface installs with its backend
  (`NeverFires`); a label leaves such a binding out. GTK answers from its conflict check.
  What the Rune side answers is open ([`owner.md`](../owner.md#b2-shared-state-out-of-the-gtk-package)).
