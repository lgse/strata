## Slice plan

1. **Slice 1 — Drag-and-drop binder, cross-volume prompt, and in-process view/tab/sidebar/crumb file drops (`feature` + `contract`):**
   - `crates/strata-app/src/dnd/` (`mod.rs`, `adapter.rs`, `router.rs`, `policy.rs`): window-scoped `Dnd` part (`Scope::Window`) attaching `strata_platform::dnd::Dnd<App>` on `host::windowed` and driving an in-window `DropZone` hit-test router on `host::offscreen` (and for sidebar-row tab drags), keeping parked-tab/unmounted drag sources live across tab hover-springs, re-evaluating held modifiers live, and running 750 ms spring-loaded opening on folder and sidebar rows.
   - `crates/strata-app/src/drop_dialog.rs`: tab-scoped `DropDialog` part (`Slot::Dialogs`) presenting C15's `"Copy or move?"` cross-volume confirmation (`[Cancel, Move, Copy]`, `Copy` focused initially, dismissal returning focus to the source row).
   - Wire drag sources and drop targets across `columns/`, `single/`, `filter/pane.rs`, `preview/`, `tab_strip`, `location/`, `sidebar.rs` (`DropInto` for folders/pins and Trash with undo, `PinHover` + `PinDrop` into bookmarks, `DropHover` spring-load, and sidebar row drags onto New tab / tab strip via `TabOpen::AtGap`), and `trash.rs`.
   - Flip passing runs in `drag_and_drop`, `drag_animation`, `cross_volume_drop`, `sidebar_file_drops`, plus cross-package drag runs in `tabs.toml`, `sidebar_pinning.toml`, `filter_results.toml`, and `pointer_intent.toml` (with `pointer_intent`'s Rune mutation patch).
2. **Slice 2 — Folder peek (`C22`) and remaining view drag-cancellation runs (`feature` + `contract`):**
   - Mount `strata_components::folder_peek::FolderPeek` in `single/` (`icons` and `list`), honouring `folder_peeking`, closing on drag start (`drag-cancels-folder-peek/{icons,list}`), and holding rest on drag end.
3. **Slice 3 — Foreign Wayland drags and content drops (`feature` + `contract`):**
   - Teach `tests/qa/foreign_drag_source.py` and `tests/qa/wayland.rs` to run the foreign GTK4 drag peer natively on Wayland (`SWAYSOCK` origin lookup) alongside X11.
   - Implement `content_drop.rs` (`save_dropped_content` over `strata_fs::services::save_dropped_files` for `application/octet-stream` images, `image/*`, web-link `.desktop` files, and plain text, with `"Unable to save dropped content"` error reporting and `open_folder_after_drop` reveal) across view panes/rows, sidebar rows, tabs, and location crumbs; flip all 15 `content_drops` runs and [A3](A3.md)'s 3 `foreign-folder-drags-validate` runs (`host = "session"`).
4. **Slice 4 — Rune mutation patches, fuzz alphabet, smoke tier, and close (`test`):**
   - Deliver one proven Rune mutation patch per scenario folder (`drag_and_drop`, `drag_animation`, `content_drops`, `cross_volume_drop`, `sidebar_file_drops`), add A19's fuzz alphabet + clean 20-seed differential smoke tier, and mark `A19` `done`.

## Notes from other packages

From [A3](A3.md) (2026-11-13): **three of A3's runs wait on a file drag from the view onto
the sidebar,** by the coordinator's ruling: `folder-pins-order-and-bookmarks`,
`spring-loaded-rows-keep-pin-intent` and `pinned-rows-transfer-and-remote-gaps`
(`tests/qa/parity/sidebar_pinning.toml`), `scope` with this package as the blocker and H4's
session host if this package needs it. `strata-app` has no drag binder, and `Dnd::rune`'s
`drag_out` starts nothing on Linux, so on the offscreen host a drag from a row reaches no
drop zone. The sidebar's zones are C8's (`PlacesSidebar::dnd`): its gaps take pins, its rows
transfers, and its intents are `PinHover`, `PinDrop`, `DropInto` and `DropHover`, which the
sidebar part (`crates/strata-app/src/sidebar.rs`) does not act on yet.
`foreign-folder-drags-validate` (3 runs) waits on [H4](H4.md) first, and then on the drops
this package wires.

From [A4](A4.md) (2026-11-14): **only the shown tab is mounted.** A hidden tab's state is
swapped out of `App` and its elements leave the tree (`crates/strata-app/src/shell/tabs.rs`).
So a drag that rests on another tab long enough to spring it (C7's `HOVER_DELAY`, 450 ms,
`hovered-tab-takes-drop`) unmounts the drag's source, the row it started on, where C7's
module docs say the host must keep every tab's view mounted while a drag runs, and on
Wayland P1 needs the source mounted at its path until the drag ends. Whoever wires the view's
drag source settles how the spring and the source live together: keep the source tab mounted
hidden during a drag, or hold the drag's payload outside the view.

From [A10](A10.md) (2026-11-15, [#2487](https://github.com/lgse/strata/pull/2487)): **one of A10's runs waits on dragging filter
