## Notes from other packages

From [A3](A3.md) (2026-11-13): **three of A3's runs wait on a file drag from the view onto
the sidebar,** by the coordinator's ruling: `folder-pins-order-and-bookmarks`,
`spring-loaded-rows-keep-pin-intent` and `pinned-rows-transfer-and-remote-gaps`
(`tests/qa/parity/sidebar_pinning.toml`), `scope` with this package as the blocker and H4's
session host if this package needs it. `strata-app` has no drag binder, and `Dnd::rune`'s
`drag_out` starts nothing on Linux, so on the offscreen host a drag from a row reaches no
drop zone. The sidebar's zones are C8's (`PlacesSidebar::dnd`): its gaps take pins, its rows
transfers, and its intents are `PinHover`, `PinDrop`, `DropInto` and `DropHover`, which the
sidebar part (`crates/strata-app/src/sidebar.rs`) does not act on yet.
`foreign-folder-drags-validate` (3 runs) waits on [H4](H4.md) first, and then on the drops
this package wires.

From [A4](A4.md) (2026-11-14): **only the shown tab is mounted.** A hidden tab's state is
swapped out of `App` and its elements leave the tree (`crates/strata-app/src/shell/tabs.rs`).
So a drag that rests on another tab long enough to spring it (C7's `HOVER_DELAY`, 450 ms,
`hovered-tab-takes-drop`) unmounts the drag's source, the row it started on, where C7's
module docs say the host must keep every tab's view mounted while a drag runs, and on
Wayland P1 needs the source mounted at its path until the drag ends. Whoever wires the view's
drag source settles how the spring and the source live together: keep the source tab mounted
hidden during a drag, or hold the drag's payload outside the view.
