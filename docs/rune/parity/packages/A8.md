## Notes from other packages

From [B1](B1.md) (2026-11-12): **the shown view is chosen once, at start.**
`slots::Registry::new` picks the view whose `shows` answers to the saved `browser_mode`, or
the first registered one; nothing changes it afterwards. A view that is not shown has no
listener and has missed every `Browser` event since start. So a live switch needs two things
in the contract, a setter for the shown view and, for the view that becomes shown, a listener
and a rebuild from the browser: a `contract` change of this package's. Parts are held to "a
part can build everything it shows again from the browser", so the rebuild has something to
stand on. The header's Appearance button is wired through [B3](B3.md)'s commands.

From [B2](B2.md) (2026-11-12): **for a folder's saved view, wait for the folder-view
store.** The model and the file code have moved ([#2168](https://github.com/lgse/strata/pull/2168), [#2188](https://github.com/lgse/strata/pull/2188)); the store, with
`begin_write`, `finish_write` and `adopt`, is B2's last pull request. Until it lands a part
does not call `load_folder_views` or `save_folder_views` itself: on GTK a saved view is read
behind `remembered_key` and the key rules of `key_for_location`, the file is read once in a
process, and two writers in one process would each save without the other's changes.

- **When a write is scheduled stays in each interface:** a change wants a write in 500 ms,
  opening a folder one in 60 s, and a pending timer is kept unless the new delay is shorter
  (delays compared, not deadlines). The two delays are exported as constants. This package
  writes the Rune side's scheduling from its loop; nothing tests the 60 s delay, the
  keep-unless-shorter rule or a touch-only write today.
- **Nothing on Rune starts the folder-view write at exit.** GTK calls
  `flush_pending_folder_views` before it quits; `crates/strata-app/src/host/windowed.rs`
  flushes the settings writer only.
- `key_for_location` reads `strata-fs`'s thread-local mount snapshot: the interface thread
  only.
- The policy that spans the settings and the folder views stays in `src/ui`'s wrapper; where
  it lives for Rune is open ([`owner.md`](../owner.md#b2-shared-state-out-of-the-gtk-package)).
- A sort chosen in a folder is stored for that folder on GTK while per-folder settings are
  on; the Rune side always stores it as the default. This package and [A10](A10.md) meet it.

From [H1](H1.md): `focus-usable-after-view-change/columns` and the slice's five Appearance
popover runs are this package's. The plan's "Decided" list gives it slice decision 21: the
Appearance popover as a host composition built from the existing slider and toggle
components.

From [A2](A2.md) (2026-11-12): **a List heading is a `column header` on Rune, a `button` on
GTK.** `view_switching/list-column-drag-applies-on-release` and
`list-column-resize-tracks-pointer` aim at a heading as `{"role":"button",…}`. The default in
force is that the QA backend presents the List table's headings as `button`, a `contract`
change to `qa/` by the first package with such a run (`packages/H3.md`, the note from A2).

From [A1](A1.md) (2026-11-12): **`show_thumbnails` is read once**, when a window is built
(`shell::thumbnail_store` in `crates/strata-app/src/shell.rs`); GTK applies it live. The
Appearance toggle that changes it calls `Window::thumbnails_mut().set_enabled(on)` when the
value changes, with `shell::saved(app).change(…)` for the save.
