## Notes from other packages

From [B1](B1.md) (2026-11-12): **the shown view is chosen once, at start.**
`slots::Registry::new` picks the view whose `shows` answers to the saved `browser_mode`, or
the first registered one; nothing changes it afterwards. A view that is not shown has no
listener and has missed every `Browser` event since start. So a live switch needs two things
in the contract, a setter for the shown view and, for the view that becomes shown, a listener
and a rebuild from the browser: a `contract` change of this package's. Parts are held to "a
part can build everything it shows again from the browser", so the rebuild has something to
stand on. The header's Appearance button is wired through [B3](B3.md)'s commands.

From [B2](B2.md) (2026-11-12): **for a folder's saved view, wait for the folder-view
store.** The model and the file code have moved ([#2168](https://github.com/lgse/strata/pull/2168), [#2188](https://github.com/lgse/strata/pull/2188)); the store, with
`begin_write`, `finish_write` and `adopt`, is B2's last pull request. Until it lands a part
does not call `load_folder_views` or `save_folder_views` itself: on GTK a saved view is read
behind `remembered_key` and the key rules of `key_for_location`, the file is read once in a
process, and two writers in one process would each save without the other's changes.

- **When a write is scheduled stays in each interface:** a change wants a write in 500 ms,
  opening a folder one in 60 s, and a pending timer is kept unless the new delay is shorter
  (delays compared, not deadlines). The two delays are exported as constants. This package
  writes the Rune side's scheduling from its loop; nothing tests the 60 s delay, the
  keep-unless-shorter rule or a touch-only write today.
- **Nothing on Rune starts the folder-view write at exit.** GTK calls
  `flush_pending_folder_views` before it quits; `crates/strata-app/src/host/windowed.rs`
  flushes the settings writer only.
- `key_for_location` reads `strata-fs`'s thread-local mount snapshot: the interface thread
  only.
- The policy that spans the settings and the folder views stays in `src/ui`'s wrapper; where
  it lives for Rune is open ([`owner.md`](../owner.md#b2-shared-state-out-of-the-gtk-package)).
- A sort chosen in a folder is stored for that folder on GTK while per-folder settings are
  on; the Rune side always stores it as the default. This package and [A10](A10.md) meet it.

From [B2](B2.md) (2026-11-12), **the folder-view store has landed** ([#2262](https://github.com/lgse/strata/pull/2262)):
`strata_desktop::settings::FolderViewStore`, described in `docs/rune/shared-state.md`, "The
store". What a part of this interface does with it:

- **One store for the process,** loaded once at start-up (`FolderViewStore::load()`), held
  where the window holds state. A second store would save without the first's changes.
- **Reading and changing:** `views()` and `views_mut()`, with a key from `key_for_location`
  (the interface thread only). The store does not carry the gate: on GTK a saved view is read
  and written only while `remember_folder_views` is on, a value equal to the default is not
  stored, and a change of a default prunes what now equals it. Those bodies are in
  `src/ui/preferences/folder_view_settings.rs`; the one that is needed moves, or is written
  again, in the package that needs it, as "The rule for a setter's body" says.
- **Writing:** the interface owns the clock. After a change ask for a write in
  `FOLDER_VIEWS_SAVE_DELAY`, after a folder was only opened in `FOLDER_VIEWS_USE_SAVE_DELAY`,
  on one timer that keeps its time unless a shorter wait is asked for. Then `begin_write`,
  await `finished()` where the interface awaits things, and act on `Written`: `Busy` asks
  again; `Saved` adopts what came back, shows it, and then calls `finish_write`.
- **At exit** a store with unsaved changes writes once more with `exit` set. Nothing on
  this interface does that yet.
- **When the file changes under the process:** `FolderViewStore::reread()`, then `adopt`.
  Nothing on this interface watches the file yet.
- **Where `finished()` is awaited:** in practice in a task spawned on GLib's context, as
  `settings::Saved::change` awaits the settings' save. GLib dispatches the end of the write
  while Rune holds the application state, so the task only queues the `Written`; `adopt` and
  `finish_write` run when the queue is applied, in `poll` or in an update.
- **Two things the types do not prevent,** and what each costs:
  - *Dropping `merged` and going straight to `finish_write`.* The file is right: every write
    merges over what is there. This process's values stay without the other process's until
    its next write, which comes back with them again, or until a reread has something to
    adopt, and a reread has nothing while this process wrote the file last.
  - *A second `begin_write` while one is out.* Both reach the file in order, each merged over
    it, and the second carries the first's changes again. `finish_write` in either order
    counts the same changes as saved.
- **A `merged` adopted late can put older values back.** `adopt` lets what it is given win
  for every folder with no unsaved change here. Adopted after a newer reread, or after a
  later write's, it brings back what the other process had saved earlier, until the next
  write or reread brings the file's. GTK adopts the same way, in the task that awaited the
  write. Here a result also waits in the queue, so apply results in the order they arrived.

Driven on the GTK build with `./scripts/qa-drive.sh` (XTest input, the canonical fixture and

- **On open** the keyboard is on the first row, the `radio menu item` "Columns"; the listing

- **Down** moves to "Icons"; **Tab** goes on to "List", **Shift+Tab** back to "Icons"; the

  sidebar's Home it opened nothing. The keyboard goes to the button.
- **A wheel outside** closes it. Over the listing it also scrolls the listing, as far as the
  same wheel does with no popover; over the sidebar it scrolls nothing in the listing.

## What dependents must know

- **The shown view changes while the window is open:** `shell::show_view(app, mode, tx)`
  (`crates/strata-app/src/shell.rs`), which the view switch's commands call. They are the
  window's own commands (`commands::own`, `commands/browser.rs`): `view-columns`,
  `view-icons` and `view-list`, defined in `crates/strata-app/src/appearance/views.rs`, for a
  menu row or a button to run by `commands::run`. The caller saves `browser_mode` and ends
  the rename first; `appearance::views::switch` does both. `appearance` is no part yet: the
  part comes with the popover's state.
- **Which view is shown, after start:** `slots::ShownView`, in `Setup::shown`. Every view's
  listener is registered at start and hears only while its view is shown; a part's timer
  asks `ShownView::is::<P>()` when it fires, as Columns' mirror does (GTK's
  `child_mirror_blocked` asks for the mode). A view not shown misses every event, and is rebuilt when it is shown
  from `events::replay`: a `Reset`, each of the browser's columns as `Added`, its rows as a
  `Rows` replacing them, its load as `Loaded` when finished or failed, and a `Selection` on
  the active column. Each column comes with `reveal`, so a single pane's remembered position
  does not come back over the browser's cursor.
- **A view gives the shell two more things** (`slots::View`): `apply`, the change its
  listener queues, through which the rebuild goes; and `returns`, for Columns alone, whether
  the selection's folder opens as the child column when the view is shown again
  (`columns_mirror_selection`, read once at start like the rest of the view's settings).
- **What follows the view shown, by the switch:** the browser's grouping by file type
  (`set_type_grouping`), as at start, and which columns its background revalidation
  rechecks (`View::rechecks`, `VisibleDepths::All` for Columns and `Active` for Icons and
  List, through `Browser::set_freshness`), at start and on each switch, both in
  `shell::mount`. The rest of `FreshnessInput` is kept as the browser has it. A setting that changes it while the window is open (the
  popover's "Group by file type") must call it again for the view shown, and lead to a
  `Rows` or `Loaded` event for the folder shown.
- **The densities** are `appearance::density::FRAME` and `CONTENT`: `saved(&Preferences)` gives
  the px a saved density stands for, by the shared rule (`strata_desktop::settings::density`),
  and the look follows both from `shell::follow_look`. A part that shows rows or bars reads
  `look.frame` and `look.content`, never the settings.
- **"Show sizes in Columns view"** is read live from the saved settings at each build of the
  Columns view, but the folders' counts are asked for only as `Columns::show_sizes` says: a
  part that changes `columns_show_sizes` (a Settings page) must call it too, or the badges
  show and no count is ever asked for ([A18](A18.md)'s note).
- **A view's own header actions** go into `pane_header::bar`'s last argument, through
  `single::group`'s: the List view passes C4's Columns button there, after the header's own
  actions. [A10](A10.md)'s sort and filter, which GTK puts before and after it, go in the same
  row in GTK's order.
- **One restore memory for the single-pane views** (`pane::Memory`, held by the shell's
  `Window`, given to each view's `Pane` as a change applies, `shell::restore_memory`): a
  folder left in Icons comes back in List where Icons left it, as GTK's one history. The
  rebuild of a view shown again does not use it, so that view shows the browser's cursor and
  scrolls to it; nor does it remember what the view showed before the switch, which is stale
  (`Memory::set_replaying`, around `shell::show_view`'s rebuild). Columns keeps no such memory.

## Open

- **After Up in List, Columns shown again opens the folder Up came from** (finding
  [#2437](https://github.com/lgse/strata/issues/2437)), where GTK's opens none: the selection
  Up placed counts as a choice on Rune. Driven on GTK. On Rune, Alt+Up in List alone already
  leaves `Browser::selection_is_load_cursor` false; the cause is in the single pane's
  `settle` (`pane.rs`), not yet pinned. Its sequence is parked.
- **Grouping by file type leaves a load's cursor where it was** (finding
  [#2427](https://github.com/lgse/strata/issues/2427)): GTK's regroup moves a cursor the load
  placed to the first row the pane shows (`sync_type_grouping`, `src/ui/browser_modes/rebuild.rs`);
  Rune's `shell::regroup` keeps it on the first entry in the folder's order. A chosen cursor
  stays on both. Its sequence is parked. GTK's List is rebuilt with no selection set
  (`apply_snapshot` sets only the filled selection), so its list's own cursor starts on the
  first row it shows; Rune's rebuild replays the browser's load cursor by id. The fix belongs
  where a rebuild (`shell::regroup`, and a switch to List) replays a provisional selection
  into a grouped column.

- **The density sliders read the saved values only when the popover opens.** GTK binds them
  live (`bind_preference` in `src/ui/window/density_slider.rs`). Nothing else changes them on
  this interface yet; a Settings window that does must have the open sliders follow it
  ([A18](A18.md)'s note). From the review of [#2394](https://github.com/lgse/strata/pull/2394).
- **Hover under an open plain popover.** What lies under the popover's surface, and the
  listing beside it, still shows hover on Rune, where GTK's popover stops it under the surface.
  Left by the owner's ruling of 2026-11-13 until Rune can block hover under a cover
  ([#2392](https://github.com/lgse/strata/issues/2392), Rune packet entry 105).
- **Two older differences in a column's background press, both C2's.** A click on the empty
  space of a column that isn't active selects its first entry in view on Rune, its first
  entry on GTK ([#2376](https://github.com/lgse/strata/issues/2376)); a drag from a column's
  background clears only that column's selection on Rune, every column's on GTK
  ([#2377](https://github.com/lgse/strata/issues/2377)). No scenario covers either yet.
- **A view chosen in one window is not followed by another.** GTK saves `browser_mode` and
  every window and tab follows the setting (`src/ui/browser/preferences.rs`). The Rune side
  follows no setting another window or process saves (`slots.rs`, "Saving a setting"), so
  this stays as it is until that changes ([A18](A18.md), [A21](A21.md)).
- **The other inputs of the browser's freshness are not set on Rune.** The window's presence
  is [A21](A21.md)'s, the power saver and `watch_network_folders` [A18](A18.md)'s, by the
  coordinator's placing; each package's file has GTK's source. The scope is this package's,
  plan item 4.

  which yields to the columns (`publish_column_width_limit`); the Rune side caps at the Columns
  view's own width, so once a preview sits beside the view the cap will be narrower than
  GTK's. A note for [A15](A15.md) says so.
- **Thumbnail jobs in flight at a view switch are not cancelled.** GTK deactivates the pane's
  models as the view leaves (`clear_inactive_mode`); the Rune side leaves a hidden view's jobs

  review of [#2343](https://github.com/lgse/strata/pull/2343).
- **No notice when a key changes the text size.** GTK shows "Text size: N px" for a moment
  after Ctrl+plus, Ctrl+minus or Ctrl+0 (`set_text_size` in `src/ui/browser/view_modes.rs`);
  this interface has no surface for such a notice yet, and no package has one.
