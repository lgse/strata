## What dependents must know

- How to write a twin is in `docs/testing.md`, "Twins", and in the `qa-scenarios` skill,
  "Write a Rune twin". A twin, its original's `parity` label, the ledger's flip to
  `parallel` and the twin's Rune mutation patch
  (`tests/qa/parity/mutations/<scenario>-rune.patch`) land in one pull request: the checks
  refuse any partial state.
- Put `./scripts/qa-parity.sh <folder> --twins` in that pull request. `--parallel` runs the
  shared file of each parallel run on Rune and names an exception that has lapsed.
- A scenario whose `targets` leave out the runner's target is no run there, so a twin moves
  no count of the GTK suite, and naming one to `./scripts/qa.sh` fails the selection with
  the command that does run it.
- A twin's run has no ledger entry of its own, so the ledger keeps listing the 760 runs of
  the shared corpus. `targets` is accepted only on a twin, and only as `["rune"]`.
- A twin's reference is an issue, `lgse/strata#<number>`, or for a `rune` twin its packet
  entry; both readers refuse any other form. What a reference looks like now that findings
  are recorded in [`findings.md`](../findings.md) is open
  ([`owner.md`](../owner.md#tracking-and-findings)).
- The slice's flaky allowance refuses a `parallel` run as it refuses a `required` one
  ([A7](A7.md)).
