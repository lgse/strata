## What dependents must know

- The ledger, its fields and its checks are in `docs/testing.md`: "The ledger", "Who owns a
  run" and "What checks the ledger". A package edits only the entries that name it.
- `./scripts/qa-parity.sh <folder|package|all> --counts` prints a selection by status and
  reason, and `--twins` lists its twins; both read files on the host and start no
  container. A run selection (`./scripts/qa-parity.sh <package>`) runs in the pinned image.
- The two readers are held to `tests/qa/parity_cases.toml`. A change to what an entry may
  hold changes that table first, and both test suites then fail until both readers agree.
- `./scripts/qa-parity.sh` refuses a selection that holds a `required` run on
  `host = "session"` until H4 teaches it the session host ([H4](H4.md)).
- A flaky allowance in `tests/qa/parity/slice.toml` may not name a `required` run, nor
  (since H2) a `parallel` one. So `new-folder-with-selection-groups/columns` cannot leave
  `pending` while the allowance names it ([A7](A7.md)).
- Nothing checks that only the owning package edits an entry, that a `required` run did pass
  three times, or what a blocker says; `docs/testing.md` says so.
