## Notes from other packages

- **Thumbnails in search results** (from [A1](A1.md), 2026-11-12): GTK's search results draw thumbnails (`src/ui/search/results.rs`, `ThumbnailSlot`). The window's store and the pool are A1's (`shell::thumbnails`, `crates/strata-app/src/thumbnails/`); a results view keeps a `thumbnails::Viewer` of its own, as `A2.md`'s notes describe.


From [B2](B2.md) (2026-11-12): **for a folder's saved sort and icon size, wait for the
folder-view store**, B2's last pull request. Until it lands a part does not call
`load_folder_views` or `save_folder_views` itself: on GTK a saved view is read behind
`remembered_key` and the key rules of `key_for_location`, the file is read once in a
process, and two writers in one process would each save without the other's changes. When a
write is scheduled stays in each interface ([A8](A8.md) has the rule).

A sort chosen in a folder is stored for that folder on GTK while per-folder settings are on;
the Rune side always stores it as the default. This package and [A8](A8.md) meet it.

The header's Search button is wired through [B3](B3.md)'s commands. The 9 `tenxer` runs of
this package's folders are [A11](A11.md)'s.

From [A2](A2.md) (2026-11-12): **a List heading is a `column header` on Rune, a `button` on
GTK.** The List heading scenarios of `view_switching` (`list-column-drag-applies-on-release`,
`list-column-resize-tracks-pointer`), and any sort scenario that clicks a heading, aim at a
heading as `{"role":"button",…}`. The default in force is that the QA backend presents the
List table's headings as `button`, a `contract` change to `qa/` by the first package with such
a run (`packages/H3.md`, the note from A2).

From [A2](A2.md) (2026-11-12): **grouped List and sorting.** With `group_by_type` on, the
List view shows a folder in strata-fs's group order; a sort change regroups through the same
path (the browser's re-sort sends `Rows`, which carry the folder's grouping).
`search_filter_sort/grouped-list-*` now render grouped on Rune; their other steps (the
location bar, the filter) remain yours and A5's.

From [A2](A2.md) (2026-11-12): **a Rune patch waiting for your grouped run.** When
`search_filter_sort/grouped-list-first-visit-starts-at-first-row/list` flips, file A2's
grouped-order mutation (its text is in `A2.md`, under #2229: `listing.rs` keeping only the
first group) as that scenario's patch, `grouped-list-first-visit-starts-at-first-row.patch`,
and prove it once by hand.
