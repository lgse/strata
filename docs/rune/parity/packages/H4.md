What the plan says of this package elsewhere, quoted with the section it is in:

- **At a glance.** H4, the session host, starts in wave 1 because all of wave 3 waits on it.
- **Verification method, "What neither loop sees".** Offscreen, input never crosses winit or a compositor. Window focus, real drag and drop, the system clipboard and decorations need the session host (H4): a real window in headless sway with a virtual keyboard and pointer.
- **What parity means, the exceptions table.** `platform` (suggested): The run needs a real window, compositor, clipboard or drag. A twin is allowed: Never. The same file runs on the session host instead of the offscreen host. Record: Ledger host field.
- **Verification method, the status table.** `required`: Passes on both targets from the shared file. Carries: the host: offscreen or session.
- **Risks.** The session host is the long pole for about 100 runs: H4 starts in wave 1. Its three areas use the offscreen host for every run that allows it.
- **Validation and gates, "Checkpoints".** End of wave 3: Drag and clipboard round trips with a second process pass on the session host. A portal open and save pass on `strata-rune`.

## Notes from other packages

From [H1](H1.md) (2026-11-12), on how the ledger treats the session host:

- A `required` entry names its `host`, `offscreen` or `session`; a `pending` one may name
  the host its run will need. One does today: `keyboard-only-copy-paste/columns`
  ([A12](A12.md), `platform`, `host = "session"`).
- `./scripts/qa-parity.sh` refuses a selection that holds a `required` run on
  `host = "session"`: it exits 2 and names the runs. So H4 teaches the script the host in
  the same pull request that flips its first drag or clipboard run. Where to lift it:
  `report_selected` and `needs_session` in `scripts/qa_parity.py`, and the scripts' test
  `test_every_required_run_of_the_committed_ledger_runs_on_the_offscreen_host`.
- If H4 changes what `host` may hold, the rows of `tests/qa/parity_cases.toml` change first.

From [H2](H2.md): a `parallel` entry may name the host its twin runs on, and `session` is
refused there as for a `required` run, so H4 need not change the schema.
