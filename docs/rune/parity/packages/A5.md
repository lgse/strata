- **What the unreadable-folder surface's tests do not reach.** Its Open as Administrator button
  has no test: no test environment offers `admin://`, so the browser's snapshot never names one.
  The `chmod 000` tests (`open_failed::tests`, the single-pane `an_unreadable_folder_says_why`,
  and `unreadable-folder-offers-retry` in the container) need a user the mode stops: as root the
  folder stays readable, and `open_failed::tests` then fails.
- **An open menu hides the rest of the window from assistive technology on Rune.** A C21
  menu is modal, so while one is open Rune's accessibility tree holds the menu alone; GTK's
  popover leaves the rest of the window in the tree (the Back history, the context menus). That
  is a difference a screen-reader user meets, not only the harness. The fix would be C21's
  (`crates/strata-components/src/context_menu/`), as a menu that does not hide the window from
  the tree; the QA backend's presentation of drawn buttons and Columns rows behind a menu only
  lets scenarios go on meanwhile.
- **The pane header, what is not on Rune yet:** GTK's spinner and truncated-listing hint
  beside the heading; the actions after it (leftovers, Empty Trash, Refresh, the sort, the
  filter: their packages', in the actions row); in the history menu, Backspace closing it and
  the vim keys moving in it (`install_menu_keys`); and the thumbnail-size button, this
  package's next pull request.
- **BackSpace in F1's shortcut reference.** GTK lists BackSpace as a row of its own, "Go to the
  parent folder" (`src/ui/shortcut_reference.rs`, the rows built from `BACKSPACE.shown()`): it is
  a bare binding, not a catalog command, so whoever ports F1 adds that row by hand.
