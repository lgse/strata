## What dependents must know

- **The folder peek** is a part of its own (`crates/strata-app/src/peek.rs`), mounted in Icons and List: `peek::rows` wraps a view's base collection with C22's anchor, `peek::with_marks` marks the anchor row, and the card is in the overlays. The shared browser lists it (`Browser::begin_peek`, the `Peek*` events), so `Browser::close_peek` or `peek::close(app)` closes it from anywhere, and returns whether one was open (Escape's first step). A cursor or selection move, results replacing the listing, navigation, a view switch and a tab switch close it too (`Peek::publish`). C22's state is on only while a keyboard peek is open; every close goes through `peek::ended`, which [A19](A19.md)'s pointer peeking makes follow `folder_peeking`.
- **10xer's preview keys:** `preview-tenxer-return` (`FOCUS_PREVIOUS`, read at `Stage::PreviewPasswordEscape`, so the archive password field hands it over) returns the keys to the listing with the drawer open. `J`/`K` (`SCROLL_PREVIEW_DOWN`/`UP`) are claimed in 10xer from the listing and the preview and step source text through `preview::scroll_lines`. `g` in a document or archive preview arms `ChordKind::PreviewTop`, whose `g` is `preview::to_top`. In 10xer the archive tree keeps Space (`on_archive_tree`).
- **The shortcut reference** lists `shortcuts::tenxer::tenxer_sections` in 10xer mode, rebuilt when the mode changes (`Built::tenxer`), and its toggle adds C19's `~` chords (`data::panel_keys(true)`). `command_sections(Map::Tenxer)` returns the window's 10xer sections of every view: Settings → Keyboard's 10xer headings come from it. The chooser's 10xer sections are [A20](A20.md)'s; until they land, `CHOOSE_FOLDER` is excused from the coverage test (`CHOOSER_ONLY`).
- **Menu hints:** `menus::Hints::of(preferences)` chooses a row's hint at open, live: the default map's (hidden when "Type to search" takes the key) or 10xer's (`Row::tenxer_hint`, `Row::no_tenxer_hint`, and `typed_hint` rows hide theirs). A new row with a 10xer verb gives it `tenxer_hint`.
- **The name highlights** ([#2570](https://github.com/lgse/strata/issues/2570)): `RowMarks::name_matches` (`NameMatches`) carries a name's matched byte ranges, and C1e's default label, C3's caption (through `NameMatches::onto` for a cut name) and C4's name cell paint them in the Kit's accent. `tenxer::highlight::{listing_marks, hit_marks}` fill them; the views' marks are named functions (`columns::row_marks`, `single::listing_marks`, `single::result_marks`). A view or label that draws a name itself applies `name_matches.spans(look)`.
- **The peek survives a reload,** as GTK's does: C22 leaves a peek open while its view shows no rows (a listing read again), and the part judges a move only once the listing is read (`peek::relisting`), by its cursor and selected entries, not C1's revision alone. The card stays the listing it opened with, as GTK's does.
- **Numbered action chords** (`tenxer/chords.rs`) list `custom_actions::numbered_actions` as `;` or `; .` arms (`ArmedActions`), and run the digit's action only while the targets and the action ids are the ones listed, else "Selection changed", "Folder changed" or "Actions changed"; `0` is the tenth.
- **The QA keyboard invariant** counts a 10xer prompt's `Holds::Prompt` as a typing hold.
- **A restored selection that is the load's pick** (`pane::restore::take_load_cursor`): when what a revisit brings back selects exactly the entries the browser's load picked, with the cursor elsewhere, the browser takes it for its own pick and keeps the load's cursor; the view takes that cursor too, as GTK's draws it, and nothing is committed (#2437).
- **Toggling 10xer** keeps the keyboard in the listing (`toggle_mode`), and 10xer's Left at the first tile in Icons stays in the view (`single::heard`'s `Intent::Edge`).

## Open

- **`R` does not restore items in the Trash.** It shows GTK's refusals; on items in the Trash it does nothing, since the Rune side has no restore from the Trash yet (GTK's `request_restore`, a loading indicator then a confirmation). No run covers it. Wire it when that restore lands.
- **`J` and `K` step only source text a line.** A text file, or a document in its source view, keeps an offset to step from (C10b's `CodeState::scroll_offset`); a rendered document, a sheet or a PDF does not, and Rune has no relative scroll (`Tx::scroll_to_y` takes an offset). There `J` and `K` do nothing, where GTK's `scroll_document` steps a line. No run reads it. It needs the offset from C11 and C12 (`on_scroll_offset`, as C10b records it), or a Rune `scroll_by`.
- **The keyboard peek of a search result.** GTK's `i` peeks a folder among filter results too (`keyboard_peek_target`'s `selected_anchor`); Rune's peeks only the listing's folders, and `i` on a result folder does nothing. No run covers it.
- **A move after a revisit** ([#2587](https://github.com/lgse/strata/issues/2587), `oracle` by the owner's ruling of 2026-11-17): a 10xer move keeps a selection a revisit restored, where GTK's first move drops it. Rune keeps its behaviour; GTK's is the fault. The `tenxer` alphabet's `h` and `l` leave only a folder with nothing selected (each after two Escapes), so a revisit restores no selection, and the shrunk sequence stays parked.
- **`tenxer-keeps-location-edit` has no patch.** Its Ctrl+F guard is held twice (10xer's page-down and the filter's own guard) and its `q` goes to the text field before any command stage; two patches were tried and missed. `keyboard_navigation`'s A11 patch is `tenxer-icons-edges-search-peek`'s.
