## Notes from other packages

From [A2](A2.md) (2026-11-12): **the contract gained `single/` and `surface.rs`**, both in
"Who owns what" in `slots.rs`. `single/` holds what the Icons and List views share beside
their pane ([#2212](https://github.com/lgse/strata/pull/2212)). `surface.rs` holds what a
listing that shows no entry says in every view, Columns included: the empty page's text, a
read's failure, or "Loading" after GTK's 150 ms grace period, with the grace kept per
listing. A Columns column now takes it through the `ColumnsView::collection` hook, which may
describe the column: C2 describes it as "Files" before the hook runs instead of after.

From [A1](A1.md) (2026-11-12): **the contract gained `thumbnails/`, `details.rs` and
`fills.rs`**, all three in "Who owns what" in `slots.rs`, with A1 as first author. `thumbnails/`
holds the render pool, a view's `Viewer` in the window's store (made with a `locate`) and the
thumbnail kinds ([#2223](https://github.com/lgse/strata/pull/2223)). `details.rs` makes the text of a row's `Facts`
for every view ([#2231](https://github.com/lgse/strata/pull/2231)). `fills.rs` asks the browser for the metadata of the rows near a
view's viewport, once a poll ([#2236](https://github.com/lgse/strata/pull/2236)). A change to any of them takes the `contract`
label and a note to the views that call it.
In the same pull request `thumbnails::Viewer::new` takes a `locate`, an entry's depth and
position in the browser, in place of `Viewer::pump`'s `resolve`, and publishes a render's
`MediaMetadata` through it. C3's details line is now a `label` in its cell's accessibility
tree, as GTK's details label is, so a probe of an Icons cell finds it.

From [A2](A2.md) (2026-11-12): **a Columns column that cannot be read** shows the message
only: a folder that cannot be read draws and describes the browser's message only; GTK's
`show_error` (`src/ui/browser/presentation.rs`) also draws a Retry button and, where the
browser offers one, an administrator button. What exists: `Browser::retry_column`, wired
today for the column menu's Refresh, and `Browser::administrator_alternative`. Unowned for
now; [A5](A5.md) has the note.

From [A2](A2.md) (2026-11-12): **file-type groups, and which index crosses the seam.**
`slots::View` gained `supports_type_grouping` (the List view's, as GTK's
`BrowserMode::supports_type_grouping`); the shell calls
`Browser::set_type_grouping(group_by_type && shown.supports_type_grouping)` once, where it
mounts the view, before the first load. A `listing::Row` carries its file type
(`listing::TypeGroup`, a key into one table of descriptions), a `Column` the browser's
grouping of its folder, and a single pane gives the collection the groups before each
`enter` and `sync`. Since #2228, `events::Added`, `Moved`, `Change::Rows` and `Change::Loaded`
carry a `grouping` field, the browser's `shows_type_groups` and `column_preferences` read in the
event reader when the event is queued; the pane follows it before the change applies, and
`Pane::apply` takes no grouping closure any more (#2226 had one). A view index is the listing's (`listing::Column`): the browser's order,
or, when the browser groups the folder by file type, strata-fs's group order
(`compare_type_groups`), each group in the browser's order. The collection's cursor, anchor,
ranges and keys (arrows, Home, End, pages, type-ahead), `Rows::neighbour` and so rename's
Tab, and the QA backend's entry order are in view indices. What crosses to the browser goes
by id and comes back as the browser's position (`Rows::position`, the handover). Anything
kept across a change of the listing, such as a restored position, is kept by id: a view
index holds only against the order the listing has now.

From [B3](B3.md) (2026-11-12), `contract` changes with the registry's entry points:

- **The window's root element has a key handler,** `commands::from_element`
  (`shell::view`). It hears what the focused element and those around it left, ahead of
  Rune's own focus navigation. The root takes no focus and no press for it.
- **The window's `on_key` walks only when nothing has the keyboard or a part says it holds
  it** (`Part::keyboard`). With an element focused and no owner, the root's handler has
  already asked.
- **The Columns adapter's `ColumnsView::collection` closure ends in `commands::in_view`**
  (`columns/view.rs`), and `single::collection` passes its collection through it.
- **`crate::parts_and(more)`** (`slots::parts!`, tests only) is the registered table with a
  test's parts after it, `test_support::view::hosted_over_in` hosts such a table in a saved
  mode, and `Entry::view` is `pub(crate)`.

From [A2](A2.md) (2026-11-12, #2234): **a host's wheel in Icons.** C1e's `on_wheel` and
`on_press` hold one handler each, and a component that sets its own replaces the host's: C3's
size wheel did. C3 now offers `IconsGrid::on_wheel`, asked before its size wheel; a view on
C3 hooks a wheel there, not on the base collection.

From [A2](A2.md) (2026-11-12): **the date format.** `App::over` (`shell.rs`) calls
`strata_core::util::set_date_format` with the saved `date_format` at start, as GTK's
`src/ui/preferences.rs` does as it loads: every date a Rune view shows (the List view's
Modified column first) reads it. It is a thread-local of the interface thread.

## What dependents must know

- **The window's thumbnails** (added by A1's thumbnail pull request, under `contract`): `shell::Window` holds one C25 `ThumbnailStore`, made from the saved `show_thumbnails` and `thumbnail_workers` (`thumbnail_store`), read by `shell::thumbnails(app)` and `Window::thumbnails_mut`. A view reads it through a `thumbnails::Viewer` of its own (`A2.md`'s notes). A Columns row would do the same: GTK's Columns rows draw a 17 px thumbnail (`src/ui/browser/columns/rows/bind.rs:234-244`), each column a viewer, its `resolve` finding the entry through the column's depth.
- **A row's thumbnail key and facts** (added by A1's thumbnail and details-line pull requests, under `contract`): `listing::Row` carries its entry's `ThumbKey` (`Column::entry` passes it on as `Entry::thumbnail`) and a `listing::Facts`, read by `Row::facts()`: size, child count, duration and dimensions, each `None` until the browser knows it. `crate::details` makes their text for every view.

- The contract is the module documentation of `crates/strata-app/src/slots.rs`; read it
  whole, "Who owns what" and "Saving a setting" included. `columns/part.rs` is the worked
  example and `docs/workspace.md` points to it.
- A part is a module and two lines in `lib.rs` under its package's comment: `mod <module>;`
  and `<field>: <module>::<State>,` inside `slots::parts!`. The package that fills a slot
  deletes the one `expect(dead_code)` line on that slot's `Place` variant, and edits
  nothing else in `slots.rs`.
- `slots.rs`, `shell.rs`, `slots/`, `host/`, `test_support.rs`, `events.rs`, `listing.rs`
  and `columns/` belong to the contract: a change there is a `contract` pull request of its
  own.
- A view's place is `Place::View(View { build, shows, focus, pointer_at, rows, editing,
  probe })`; a sidebar's is `Place::Sidebar(Sidebar { build, focus })`; an overlay or a
  dialog pushes its surfaces on `Frame::layer`. `test_support::hosted_over` tests a place
  without registering it. The notes left for [A1](A1.md), [A2](A2.md), [A3](A3.md),
  [A4](A4.md), [A8](A8.md) and [H3](H3.md) are in their files.
- A part keeps no `Rc<Browser>` of its own, reads `app.browser` at the call and can build
  everything it shows again from the browser, so that tabs ([A4](A4.md)) and a live view
  switch ([A8](A8.md)) stay open.
- Window chords and the header's five buttons were to wait on [B3](B3.md). `WINDOW_KEYS`
  and `shell::on_key` are gone since [#2210](https://github.com/lgse/strata/pull/2210): the
  keys, the menu rows and the buttons are the command registry's
  (`crates/strata-app/src/commands.rs`), and [B3](B3.md), "What dependents must know", says
  what a part registers and when.
