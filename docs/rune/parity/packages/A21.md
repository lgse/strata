## Notes from other packages

- **One thumbnail store per window** (from [A1](A1.md), 2026-11-12): C25's `ThumbnailStore` is in each window's shell, the render pool is per process. GTK holds its decoded images once per process (`THUMBNAIL_CACHE` in `src/ui/thumbnail/cache.rs`), so with several windows the Rune side decodes and holds an image once per window. Yours to settle with multi-window: a shared byte budget, or one store. Nothing a user sees differs (`owner.md`, A1 item 7).


From [H1](H1.md): one of the slice's pending runs, in `startup_arguments` (a window per

From [A8](A8.md) (2026-11-14), placed by the coordinator: **the window's presence for the
browser's revalidation is this package's.** GTK feeds `Browser::set_freshness` a
`FreshnessInput` whose `presence` follows the window: `Hidden` while it is unmapped,
suspended or minimized, `Focused` while it is active, `Visible` otherwise
(`presence_of` in `src/ui/presence.rs`), wired per window in
`src/ui/window/composition/tabs.rs` (`presence::follow`) to `BrowserView::set_presence`
(`src/ui/browser/view_modes.rs`), which also tells the path completion. The browser's checks
follow it (`regain_focus` and `follow_responsiveness` in
`crates/strata-fs/src/app/browser/freshness.rs`). The Rune side never calls
`set_freshness`, so the browser keeps its default, `Visible`, whatever the window does. The
input's `scope` is A8's; its power saver and `watch_network_folders` are [A18](A18.md)'s.
