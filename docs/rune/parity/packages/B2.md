## Remaining work, in order

1. **The key catalog's move, behind the seam:** the key and modifier types, the catalog,
   `registry()`, `Keymap`, `KeyPress` and `KeyPress::from_parts`, `rewrite` and `label`,
   with every GDK call replaced by a backend call and the GDK backend in `src/ui`; the one
   line of `quick-preview.patch`, proved with `./scripts/qa-mutation.sh quick-preview`. No
   new dependency. [B3](B3.md) waits for this.
2. **The `xkbcommon` backend's lookups and difference rules,** with a GTK-lane test that
   compares them with GDK over the whole keysym range and fails on any difference the rules
   do not cover.
3. **The accelerator reader and writer for the `xkbcommon` backend,** written by a session
   that has not read GTK's source, from GTK's documented format and from probing GTK as a
   black box.
4. **The folder-view store:** `begin_write`, `finish_write` and `adopt`, with the timer rule
   left in each interface. Owed by it, from the review of [#2188](https://github.com/lgse/strata/pull/2188): direct tests of
   `save_folder_views` and `load_folder_views` in `strata-desktop`, and a row in the merge
   table for new code on `main` that uses an import `folder_view_settings.rs` dropped.

The keymap methods of `PreferenceManager` follow the catalog's move (the ruling of
2026-11-12 on the `PreferenceManager` shape); the last order of work does not place them,
and the package's agent says where when it gets there.

## What dependents must know

- `docs/rune/shared-state.md` is where every move is described, with what a merge from
  `main` does with each moved file. A moved file takes no new code on `strata-next`: new
  shared code goes in a new file beside it.
- **Saving a setting** on the Rune side is `shell::saved(app).change(|settings| …)`, from a
  handler or a queued update, under the rules in `slots.rs`, "Saving a setting". A setter's
  body that does more than assign moves, when a Rune package first needs it, onto
  `Preferences` or a free function in `strata_desktop::settings`, in that package's own
  `contract` pull request ([A18](A18.md) has the list of such bodies).
- **Tab sessions** for [A4](A4.md): `load_restorable()` at start-up only (it blocks);
  `save` and `remove` queue and may be called from `poll` or an update. The rules for using
  the store are in GTK code and are listed in `docs/rune/shared-state.md`, "Tab sessions".
- **Folder views** for [A8](A8.md) and [A10](A10.md): wait for the store. A part does not
  call `load_folder_views` or `save_folder_views` itself.
- **Keys** for [B3](B3.md), [A6](A6.md), [A18](A18.md) and [H3](H3.md): what arrives with
  the move, the conformance corpus every press builder must pass, the one shared reading of
  the US table, and the cases where GTK and Rune would disagree are in [B3](B3.md).
- **What still differs** between the two interfaces' settings behaviour, each with the
  package that meets it, is in [A18](A18.md) and in `docs/rune/shared-state.md`.
- `src/ui/keys/conflicts.rs` stays in `src/ui` when the catalog moves; the Rune side gets
  no conflict check ([A6](A6.md), [A18](A18.md)).
