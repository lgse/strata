reads keys, accelerator strings and a saved keymap through `keys::Xkb`; of
`PreferenceManager`, the bookkeeping of saving moved, and resolving a saved keymap. The
items on `PreferenceManager` and on the toolkit-free parts are ticked by the owner's two
rulings of 2026-11-12 ([`owner.md`](../owner.md#ruled)): the bookkeeping-only shape meets the ruling, with
setters moving on demand, and B2 closes with the folder-view timer rule left in each
interface.

What stays in `src/ui`, and where each goes:

- **`PreferenceManager`'s getters, setters, bindings and notices.** A setter's body that
  does more than assign moves onto `Preferences` or a free function in
  `strata_desktop::settings` with the Rune package that first needs it, in that package's
  `contract` pull request ([A18](A18.md) has the list; `docs/rune/shared-state.md`, "The rule
  for a setter's body").
- **The edits to a saved keymap** (`set_bindings`, `reset_binding`, `reset_map`): onto
  `KeymapOverrides`, in a new file beside `settings/keymap.rs`, with [A18](A18.md)'s keyboard
  settings.
- **The policy around the per-folder values** (`set_remember_folder_views`,
  `set_default_sort_options`, `set_folder_icons_size`, `set_default_icons_size`): with
  [A8](A8.md) and [A10](A10.md), where the owner's open question on where it lives is
  answered.
- **The folder-view store's timer, monitors and trashed folders' values:** each interface
  keeps its own, by the owner's ruling.
- **The keymap's revision, `shown_keys` and the conflict report:** GTK's bindings and GTK's
  conflict check (`src/ui/keys/conflicts.rs`), with no Rune counterpart; which conflicts
  Rune reports is [A6](A6.md)'s and [A18](A18.md)'s question for the owner.
- **The reader of GDK events, the native aliases, capture and composition** in `src/ui/keys`,
  and GDK's key backend: they go with GTK.

`docs/rune/shared-state.md` has the table of what moved.

## What dependents must know

- `docs/rune/shared-state.md` is where every move is described, with what a merge from
  `main` does with each moved file. A moved file takes no new code on `strata-next`: new
  shared code goes in a new file beside it.
- **Saving a setting** on the Rune side is `shell::saved(app).change(|settings| …)`, from a
  handler or a queued update, under the rules in `slots.rs`, "Saving a setting". A setter's
  body that does more than assign moves, when a Rune package first needs it, onto
  `Preferences` or a free function in `strata_desktop::settings`, in that package's own
  `contract` pull request ([A18](A18.md) has the list of such bodies).
- **Tab sessions** for [A4](A4.md): `load_restorable()` at start-up only (it blocks);
  `save` and `remove` queue and may be called from `poll` or an update. The rules for using
  the store are in GTK code and are listed in `docs/rune/shared-state.md`, "Tab sessions".
- **Folder views** for [A8](A8.md) and [A10](A10.md): the store is
  `strata_desktop::settings::FolderViewStore` (`docs/rune/shared-state.md`, "The store").
  One for the process, loaded at start-up; a part does not call `load_folder_views` or
  `save_folder_views` itself. The interface owns the clock: it asks for a write 500 ms
  after a change and 60 s after a folder was only opened, tries a busy write again, and
  writes once more at exit. The gate (`remember_folder_views`), the key rules and what is
  stored relative to the defaults are policy in GTK's `PreferenceManager` methods, not in
  the store.
- **Keys** for [B3](B3.md), [A6](A6.md), [A18](A18.md) and [H3](H3.md).
  `docs/rune/shared-state.md`, "The key catalog", describes `strata_desktop::keys`.
  - **The seam for a press** is `KeyPress::from_parts(KeyPressParts { … })`, then
    `rewrite(press, Context { typing })`, then `press.is(…)`. Nobody fakes a GDK event.
  - **The key library is the interface's.** A key's name, character and case, and reading
    and writing an accelerator string, are asked of the `Backend` an interface installs
    once with `keys::install`. **The Rune side's is `keys::Xkb`**, which `strata-app`
    installs when the UI thread is claimed, so in any host or hosted test `from_parts`,
    `from_signal`, `rewrite`, `press.is(…)` and the labels work. It answers what GDK
    answers for every key, name and character, for the test image's libraries: the table
    for the keys the code declares, libxkbcommon for the rest
    (`docs/rune/shared-state.md`, "What `Xkb` answers"). It reads and writes accelerator
    strings as GTK does, so `Binding::parse` and `Binding::accelerator` work there, and
    **the Rune side reads a saved keymap**: `commands::Live` holds what
    `settings::resolve_keymap` gives for the saved overrides, and resolves them again when
    a saved change differs (`docs/rune/shared-state.md`, "The keymap methods"). A plain test in
    `strata-app` that asks about a key calls `startup::install_key_library()` first; a
    test in `strata-desktop` calls `keys::Table` or `keys::Xkb` directly, or installs one
    in a process of its own.
  - **A key constant goes in `crates/strata-desktop/src/keys/key_constants.rs`,** for
    any named key an interface delivers, whether or not the catalog binds it. While GTK
    exists a GTK-lane test holds each to GDK's key of the same name, so a name GDK does
    not read is raised first, not added quietly.
  - **The live settings** (10xer on, type-to-search, the keymap) reach the catalog
    through the `Active` an interface registers with `keys::set_active`: one slot for the
    thread, holding a weak reference.
  - The conformance corpus every press builder must pass, the one shared reading of the
    US table, and the cases where GTK and Rune would disagree are in [B3](B3.md).
- **A test file under `src/ui` that moves or is renamed** takes the name strings of its
  GTK tests with it, or they pass without running (finding [#2193](https://github.com/lgse/strata/issues/2193) in
  [`findings.md`](../findings.md)).
- **What still differs** between the two interfaces' settings behaviour, each with the
  package that meets it, is in [A18](A18.md) and in `docs/rune/shared-state.md`.
- `src/ui/keys/conflicts.rs` stays in `src/ui` when the catalog moves; the Rune side gets
  no conflict check ([A6](A6.md), [A18](A18.md)).
