Where the list stands: tab sessions moved whole. Of `PreferenceManager`, the bookkeeping of
saving moved and the Rune interface saves through it; its getters and setters stay in
`src/ui`, which is a narrower reading of "moved" than the plan's words (see Open). Of the
per-folder views, the model and the file code moved; the store has not. The key catalog
moved, and the GTK application uses it through a backend seam. The Rune side has a backend
for the keys the code declares; its item is ticked when the Rune side can also read a saved
keymap, which is the rest of the remaining work on keys.
`docs/rune/shared-state.md` has the table of what moved.

## What dependents must know

- `docs/rune/shared-state.md` is where every move is described, with what a merge from
  `main` does with each moved file. A moved file takes no new code on `strata-next`: new
  shared code goes in a new file beside it.
- **Saving a setting** on the Rune side is `shell::saved(app).change(|settings| …)`, from a
  handler or a queued update, under the rules in `slots.rs`, "Saving a setting". A setter's
  body that does more than assign moves, when a Rune package first needs it, onto
  `Preferences` or a free function in `strata_desktop::settings`, in that package's own
  `contract` pull request ([A18](A18.md) has the list of such bodies).
- **Tab sessions** for [A4](A4.md): `load_restorable()` at start-up only (it blocks);
  `save` and `remove` queue and may be called from `poll` or an update. The rules for using
  the store are in GTK code and are listed in `docs/rune/shared-state.md`, "Tab sessions".
- **Folder views** for [A8](A8.md) and [A10](A10.md): wait for the store. A part does not
  call `load_folder_views` or `save_folder_views` itself.
- **Keys** for [B3](B3.md), [A6](A6.md), [A18](A18.md) and [H3](H3.md).
  `docs/rune/shared-state.md`, "The key catalog", describes `strata_desktop::keys`.
  - **The seam for a press** is `KeyPress::from_parts(KeyPressParts { … })`, then
    `rewrite(press, Context { typing })`, then `press.is(…)`. Nobody fakes a GDK event.
  - **The key library is the interface's.** A key's name, character and case, and reading
    and writing an accelerator string, are asked of the `Backend` an interface installs
    once with `keys::install`. **The Rune side's is `keys::Table`**, which `strata-app`
    installs when the UI thread is claimed, so in any host or hosted test `from_parts`,
    `rewrite`, `press.is(…)` and the labels work for every catalog entry. It answers for
    the keys the code declares and for characters, and for nothing else: a key the code
    does not declare has no name, no named key but a keypad key types anything, only ASCII
    letters have another case, and no accelerator string is read or written, so **a saved
    keymap is not read on the Rune side** until the accelerator reader lands, and
    `Binding::accelerator` panics there. `normalize` and `KeyPress::from_signal` find no
    Latin fallback on a non-Latin layout with it, so a press there is built with
    `from_parts`. `docs/rune/shared-state.md` has the table of what it answers, and
    [B3](B3.md) the lists of what works and what waits. A plain test in `strata-app` that
    asks about a key calls `startup::install_key_library()` first.
  - **A key constant goes in `crates/strata-desktop/src/keys/key_constants.rs`,** for
    any named key an interface delivers, whether or not the catalog binds it. While GTK
    exists a GTK-lane test holds each to GDK's key of the same name, so a name GDK does
    not read is raised first, not added quietly.
  - **The live settings** (10xer on, type-to-search, the keymap) reach the catalog
    through the `Active` an interface registers with `keys::set_active`: one slot for the
    thread, holding a weak reference.
  - The conformance corpus every press builder must pass, the one shared reading of the
    US table, and the cases where GTK and Rune would disagree are in [B3](B3.md).
- **A test file under `src/ui` that moves or is renamed** takes the name strings of its
  GTK tests with it, or they pass without running (finding [#2193](https://github.com/lgse/strata/issues/2193) in
  [`findings.md`](../findings.md)).
- **What still differs** between the two interfaces' settings behaviour, each with the
  package that meets it, is in [A18](A18.md) and in `docs/rune/shared-state.md`.
- `src/ui/keys/conflicts.rs` stays in `src/ui` when the catalog moves; the Rune side gets
  no conflict check ([A6](A6.md), [A18](A18.md)).
