From [A2](A2.md) (2026-11-12): **the List view's file-type groups reorder a pane's
listing.** A `listing::Column` the browser groups shows its rows in strata-fs's group order,
and a single pane gives the collection its groups. The rule, in [B1](B1.md)'s notes: A view
index is the listing's (`listing::Column`): the browser's order, or, when the browser groups
the folder by file type, strata-fs's group order (`compare_type_groups`), each group in the
browser's order. The collection's cursor, anchor, ranges and keys (arrows, Home, End, pages,
type-ahead), `Rows::neighbour` and so rename's Tab, and the QA backend's entry order are in
view indices. What crosses to the browser goes by id and comes back as the browser's
position (`Rows::position`, the handover). Anything kept across a change of the listing,
such as a restored position, is kept by id: a view index holds only against the order the
listing has now. The Icons view never groups (the browser groups only for a view that
supports it), so nothing changes for it; the position restore you plan for `Pane` must keep
the row by id, or by view index against the order the listing has then.

so nothing in an ungrouped view pays a MIME lookup.

## What dependents must know

- **The cursor and selection handover is shared:** `crates/strata-app/src/handover.rs`
  (`Held`, `adopt`, `hand_over`, `sync_rule`, `placed`, `Moving`). The Columns adapter
  uses it once for each column. A view does not copy it.
- **A single-pane view stands on `crate::pane::Pane`** (`crates/strata-app/src/pane.rs`):
  the browser's active column, with a listing kept for every column so the one the browser
  makes active shows at once, as GTK rebuilds its pane from `active_depth`. Its collection
  is private: the component's handlers take it through `parts_mut`, and `publish` hands it
  over. Positions and neighbours are in listing order, so a view that groups its rows
  ([A2](A2.md)'s file-type groups) maps through its groups first. Its `scope` is one key
  for the window; tabs ([A4](A4.md)) will need one per tab.
- Both modules belong to the contract (`slots.rs`, "Who owns what"): a change to them is a
  `contract` pull request of its own.
- `events::Change::Truncated` carries `active`, the browser's active column once the
  others closed.
- **A row's facts are shared:** `listing::Row::facts()` gives `listing::Facts` (size, child
  count, duration, dimensions, each `None` until the browser knows it), and
  `crates/strata-app/src/details.rs` makes their text for every view. A view does not
  format a size, a duration or an item count of its own.
- **Metadata fills are shared:** `crates/strata-app/src/fills.rs`. A view keeps a `Fills`,
  records its range from `on_visible` (`Fills::see`) and asks once a poll
  (`Fills::request(&app.browser, depth, listing)`), as Icons does in `icons/part.rs`.
- **A view's thumbnail viewer says where an entry is:** `thumbnails::Viewer::new(later,
  locate)`, `locate` giving an entry's depth and position in the browser. The viewer finds
  the file through it, and publishes a render's `MediaMetadata` to the browser through it.
- **A viewer may speak for several of the store's viewers:** `Viewer::fit(store, count)` keeps one per part (Columns' columns), dropping the last ones as parts close, and `Viewer::id_at(index)` names each. A single-pane view needs neither: its first pump takes one.
- **What A1 leaves to [A2](A2.md) in `details.rs`:** the List columns' text that Icons has no
  use for, `format_permissions` (the Mode column) among them, and `entry_size`'s rule for
  the size column. A2 adds them there, with the modified time it adds to `Facts`, in its own
  `contract` change; A1 adds nothing more to the module for List, so neither waits on the
  other.
- **For [A2](A2.md):**
  - A grouped List view has no way in yet. C4's file-type groups need
    `CollectionState::set_groups` before `enter` or `sync`
    (`crates/strata-components/src/list_table/mod.rs`, around line 85). `Pane` calls both
    itself, with the collection private. Grouping also needs contiguous groups, while the
    listing is in the browser's order. That is a `contract` change A2 asks for, for example
    a groups hook that `Pane` applies before each `enter` and `sync`.
  - Sideways arrows in List: plain Left and `h` go to the sidebar when it can take the
    keyboard, since GTK's `at_left_edge` is true in any mode but Icons
    (`src/ui/browser_modes/focus.rs:133-136`). `Stay` (`horizontal_arrow_action` in
    `src/ui/window/key_routing.rs`) is for Right, for Shift or Ctrl with a sideways arrow,
    and when the sidebar is hidden.
  - GTK's Icons view never groups by file type: `BrowserMode::supports_type_grouping` is
    true for List only (`src/ui/browser_modes.rs:111-114`, "Icons clustering is wired but
    gated off"). `group_by_type` changes nothing in Icons.
  - The QA backend reads `selected` and `focused` from the tree, not from `Browser`. Pin the
    browser's side of the selection with a unit test, as `icons::tests` does with
    `assert_browser_agrees`.
  - `Pane`'s `scope` is one key for the window, until tabs ([A4](A4.md)).

## Open

- **GTK's 0.72 opacity for a file's icon in Columns rows** (`bind.rs:247`, `:279` for search results) is not on the Rune row, which draws every icon at full opacity: a C2 row-look change under `contract`, A1's, after the position restore, announced before it opens. Also in `B1.md`'s "Open".
- **A Columns column scrolled off the strip sideways still asks for thumbnails;** GTK's viewport priority checks the x bounds too (`viewport.rs:263-275`). C2 does not expose a column's place along the strip, so `columns/thumbs.rs` does not skip one. Also in `B1.md`'s "Open".
- **`idle-workers-exit-and-restart/columns` waits for the retired count to equal the workers first started** (line 10). On Rune today nothing asks again once the folder is cached, so the run is sound. A later change that asks for thumbnails again between lines 5 and 10 (Columns fills, an eviction, a step change) could start a new sandbox, push the count past `$original`, and make the run fail rather than wait. Recheck it with three rounds when Columns fills land.
- **A Columns-specific mutation, not made:** `idle-workers-exit-and-restart.patch` (a free name) would make `columns/thumbs.rs`'s `poll` never call `store.sync` for a column, expected to fail at line 5. The folder has its one patch, the sync has its table test, and the owner's rule keeps mutation work to cases where a test's effectiveness is in question; it is recorded for whoever next doubts the Columns runs.
- **Metadata fills for Columns,** a later change of its own: GTK's Columns rows ask for fills (`request_metadata` in `src/ui/browser/columns/rows/bind.rs`) only while the view is not scrolling, and with a folder's count only while sizes are shown. Rune's Columns asks for none yet. `Fills` would need a mode that asks for a folder's count without a file's image details, a pause while the column scrolls, and the sizes setting as its switch.
- **The fills' margin is counted in entries, not pixels.** `fills.rs` widens the visible range by a quarter of its entries each way and does not round to whole rows of tiles, so a partial row at the edge may be half asked for; GTK's margin is a quarter of the viewport in pixels (`visibility` in `src/ui/thumbnail/viewport.rs`).
- **Settings read once.** `show_thumbnails` and `thumbnail_workers` are read when a window is built (`shell::thumbnail_store`); GTK applies both live. Whoever adds the control calls `Window::thumbnails_mut().set_enabled(on)` and `strata_preview::sandbox::browser::set_worker_limit(n)` when the value changes: the Appearance toggle is [A8](A8.md)'s, the workers spin button [A18](A18.md)'s. Not A1's to build.
- **No hold for a running file operation.** GTK parks a file a copy or move holds and admits it again on release (`HELD_FOR_OPERATION`, `admit_after_release` in `src/ui/thumbnail/jobs.rs`). Here the render fails (`strata-preview` refuses a held file, or finds "Browser input changed while rendering"), and the store records the failure. It heals by itself: when the copy ends, the browser reads the file's new modification time and size and the row's key changes, so the new key is asked for; a key that stays the same (a move keeps both) is asked again after the store's `retry_after`, 30 s, GTK's `FAILED_THUMBNAIL_TTL`. Until then the tile shows its icon where GTK shows the thumbnail at release. Noted in [A12](A12.md), whose copies are the first the Rune side runs.
- **The camera kind is left out** of `thumbnails/kind.rs`: GTK takes a camera file's thumbnail from GIO's preview icon of a `gphoto2://` location, through `strata_preview::services::camera_preview`. It waits on a camera's folder opening on the Rune side, which no package names yet, and a key for a location that is not a local path (`thumbnails::key_of` gives none).
