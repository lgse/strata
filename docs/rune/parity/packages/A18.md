## Notes from other packages

From [B2](B2.md) (2026-11-12):

- **What B2 moves of `PreferenceManager`: the bookkeeping, not the setters.**
  `strata_desktop::settings::Saving` ([#2172](https://github.com/lgse/strata/pull/2172)) holds the save bookkeeping, and a Rune part
  changes a setting with `shell::saved(app).change(…)` ([#2178](https://github.com/lgse/strata/pull/2178)). Every getter and setter
  stays in `src/ui/preferences`. A setter's body that does more than assign moves when a
  Rune package first needs it, onto `Preferences` or a free function in
  `strata_desktop::settings`, in that package's own `contract` pull request, with the GTK
  setter calling it. Every range rule is already shared, in `Preferences::normalize_loaded`.
- **The bodies whose logic exists only in the method today**, by B2's reading (it may
  differ at the edges): `set_omarchy_variant`, `set_active_omarchy_theme` and
  `omarchy_variant` (`appearance_settings.rs`); `set_device_label`, `device_label`,
  `remember_send_to_destination` and `folder_color` (`file_settings.rs`);
  `set_browser_column_width`, `set_chooser_column_width`, `set_list_column_visible` and
  `move_list_column` (`layout_settings.rs`); `set_video_preview_backend`,
  `set_preview_audio` and `set_hardware_accelerated_video_previews`
  (`preview_settings.rs`). The archived issue's comment of 2026-11-12 says what only each
  knows.
- **Not repaired when the file loads**, so a Rune reader checks them as GTK's getters do:
  device labels, custom icon names, the send-to history and the stored strings of enums.
- **The exhaustive saved-preferences fixture stays GTK-only** (`src/ui/preferences/fixtures.rs`
  and the setter-coverage test). It needs a home before `src/ui` is deleted, and the Rune
  write path has no equivalent coverage ([`owner.md`](../owner.md#b2-shared-state-out-of-the-gtk-package)).
- **Where the Rune interface's settings still differ from GTK's** after B2's work:

  | | GTK | The Rune interface | Package |
  | --- | --- | --- | --- |
  | Start-up effects | Applies the language, reduced motion and the date format | Applies the language only | A18 |
  | A change another process saves | Adopts the sort and the icon size, and re-reads folder views | Follows nothing | A18 |
  | A sort chosen in a folder | Stored for that folder while per-folder settings are on, and as the default otherwise | Always stored as the default | [A8](A8.md), [A10](A10.md) |
  | A file that could not be read at start-up | A notice on the first change, and nothing saved over it | Nothing saved over it, and no notice after the warning in the log | A18 |

From [B1](B1.md): `settings.rs` in `strata-app` is B2's and then this package's. The

From [H1](H1.md): the 9 runs of [A6](A6.md)'s folders that work in the Settings window are

From [A1](A1.md) (2026-11-12): **`show_thumbnails` and `thumbnail_workers` are read once**,
when a window is built (`shell::thumbnail_store` in `crates/strata-app/src/shell.rs`); GTK
applies both live. The control that changes one calls, when the value changes,
`Window::thumbnails_mut().set_enabled(on)` for `show_thumbnails`, and
`strata_preview::sandbox::browser::set_worker_limit(n)` for `thumbnail_workers` (the workers
spin button). The limit is per process: it is the pool's, not the window's.

From [A2](A2.md) (2026-11-12): **a live change to the date format must set it again.** The
Rune shell calls `strata_core::util::set_date_format` once, at start (`shell.rs`, `App::over`).
When Settings changes `date_format` on the Rune side, it calls `set_date_format` with the new
value before it saves, as GTK's `PreferenceManager::set_date_format`
(`src/ui/preferences/file_settings.rs`) does, and the views showing dates (the List view's
Modified column) draw again.
