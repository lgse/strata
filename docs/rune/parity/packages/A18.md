From [B2](B2.md) (2026-11-12):

- **What B2 moves of `PreferenceManager`: the bookkeeping, not the setters.**
  `strata_desktop::settings::Saving` ([#2172](https://github.com/lgse/strata/pull/2172)) holds the save bookkeeping, and a Rune part

  stays in `src/ui/preferences`. A setter's body that does more than assign moves when a
  Rune package first needs it, onto `Preferences` or a free function in
  `strata_desktop::settings`, in that package's own `contract` pull request, with the GTK
  setter calling it. Every range rule is already shared, in `Preferences::normalize_loaded`.
- **The bodies whose logic exists only in the method today**, by B2's reading (it may
  differ at the edges): `set_omarchy_variant`, `set_active_omarchy_theme` and
  `omarchy_variant` (`appearance_settings.rs`); `set_device_label`, `device_label`,
  `remember_send_to_destination` and `folder_color` (`file_settings.rs`);

  `move_list_column` (`layout_settings.rs`); `set_video_preview_backend`,
  `set_preview_audio` and `set_hardware_accelerated_video_previews`

  knows.
- **Not repaired when the file loads**, so a Rune reader checks them as GTK's getters do:
  device labels, custom icon names, the send-to history and the stored strings of enums.

  and the setter-coverage test). It needs a home before `src/ui` is deleted, and the Rune

- **Where the Rune interface's settings still differ from GTK's** after B2's work:

  | | GTK | The Rune interface | Package |

From [A1](A1.md) (2026-11-12): **`show_thumbnails` and `thumbnail_workers` are read once**,
when a window is built (`shell::thumbnail_store` in `crates/strata-app/src/shell.rs`); GTK
applies both live. The control that changes one calls, when the value changes,
`Window::thumbnails_mut().set_enabled(on)` for `show_thumbnails`, and
`strata_preview::sandbox::browser::set_worker_limit(n)` for `thumbnail_workers` (the workers
spin button). The limit is per process: it is the pool's, not the window's.

From [A2](A2.md) (2026-11-12): **a live change to the date format must set it again.** The
Rune shell calls `strata_core::util::set_date_format` once, at start (`shell.rs`, `App::over`).
When Settings changes `date_format` on the Rune side, it calls `set_date_format` with the new
value before it saves, as GTK's `PreferenceManager::set_date_format`
(`src/ui/preferences/file_settings.rs`) does, and the views showing dates (the List view's
Modified column) draw again.

From [B2](B2.md) (2026-11-13), **the edits to a saved keymap are this package's to move**
when it builds the keyboard settings. `set_bindings`, `reset_binding` and `reset_map` of
GTK's `PreferenceManager` (`src/ui/preferences/keymap.rs`) are a few lines each over
`strata_desktop::settings::KeymapOverrides` and hold the file's rules: bindings saved in
their normalized form with repeats dropped, the shipped bindings removing the entry, an
empty list unbinding, a map's reset keeping the ids this version does not know. They go
onto `KeymapOverrides` in a new file beside `settings/keymap.rs`, in a `contract` pull
request, with the GTK methods calling them; write none of them a second time. They cannot
run on this interface until its key library writes accelerator strings
(`Binding::accelerator` panics before), and the conflict check they are used with on GTK
stays in `src/ui` (the question above). `docs/rune/shared-state.md`, "The keymap methods".

From [B2](B2.md) (2026-11-13, [#2274](https://github.com/lgse/strata/pull/2274)): **`Binding::accelerator` no longer panics
on this interface** once #2274 merges: its key library, `keys::Xkb`, then reads and writes
accelerator strings as GTK does. So the keymap edits in the note above are not blocked by
it; the conflict check they are used with on GTK is still the open question.

From [A3](A3.md) (2026-11-13): **the sidebar reads its settings when the window starts.**
GTK's sidebar rebuilds when `sidebar_order`, a place's `sidebar_show_*` or a section's
collapsed state changes, from Settings or another window (`bind_order` in
`src/ui/window/sidebar.rs`). The Rune sidebar (`crates/strata-app/src/sidebar.rs`) reads them
once and changes only what it saves itself (a section's heading), so a Settings page that
changes them needs the sidebar to list its rows again (`relist` there), which it does not
do yet for a change made elsewhere.

From [A8](A8.md) (2026-11-13), from the review of
[#2402](https://github.com/lgse/strata/pull/2402): **a Settings page that changes
`columns_show_sizes` must also call `Columns::show_sizes`.** The Columns view's badges read the
saved setting at each build, but the open columns ask for their folders' counts only as
`Columns::show_sizes` tells them; the Appearance popover's row calls both. Without the call,
the badges show and the folders' counts are never asked for.

From [A8](A8.md) (2026-11-13), from the review of
[#2394](https://github.com/lgse/strata/pull/2394): **the Appearance popover's density sliders
read the saved values only when it opens** (`appearance::density`, `Density::follow_saved`).
GTK binds them live (`bind_preference` in `src/ui/window/density_slider.rs`). A Settings page
that changes `frame_density` or `browser_density` while the popover is open must have its
sliders follow, as `follow_saved` does; the look already follows through `shell::follow_look`.

From [A8](A8.md) (2026-11-13), placed by the coordinator: **two inputs of the browser's
revalidation are this package's.** GTK feeds `Browser::set_freshness` a `FreshnessInput`
with:
- `watch_network_folders`, the saved setting, bound live (`src/ui/browser/preferences.rs`
  to `BrowserView::set_watch_network_folders` in `src/ui/browser/view_modes.rs`): whether a
  folder that other machines can write is rechecked;
- `power_saver`, the system's power-saver state (`follow_power_saver` in
  `src/ui/presence.rs`, from GIO's power profile monitor), set with the window's presence
  through `BrowserView::set_presence`.

The Rune side never calls `set_freshness`, so the browser keeps its defaults: network folders
watched and no power saver, whatever is saved or the system says. The input's `scope` is
A8's; the window's presence is [A21](A21.md)'s.

From [A10](A10.md) (2026-11-14, [#2439](https://github.com/lgse/strata/pull/2439)):
**`remember_folder_views` is read once for the folders' sorts**, when the window starts
(`folder_views::Kept::follow_sorts` in `crates/strata-app/src/folder_views.rs`). GTK binds
it live (`src/ui/browser/preferences.rs`). The control that turns it on or off calls the
browser's `set_folder_sorts` with the store's resolver when on and `None` when off, and
`set_remember_folder_views` (shared) for what it prunes.
