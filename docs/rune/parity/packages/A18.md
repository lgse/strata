## Notes from other packages

From [A21](A21.md) (2026-11-19, [#2605](https://github.com/lgse/strata/pull/2605)): **a restart
from Settings that a close guard refuses relaunches Strata later, unasked.**
`settings_dialog::restart_process` starts its relaunch helper, then closes its window through
`shell::close_window`. When a guard refuses (a file operation, or a job on the last window), the
helper still waits for the process to end, and when it does end, for example once the copy
finishes and the user closes the window, it relaunches Strata. GTK checks every window's
guards before it starts anything (`restart_blocker_shown` in `src/ui/settings/restart.rs`).
Asking `shell::close_guard::refusal` before the helper starts, across the windows, would match
it. Recorded in A21's "Open"; yours to fix.

From [A21](A21.md) (2026-11-17, [#2594](https://github.com/lgse/strata/pull/2594)): **`preferences/preferences-sync-windows-restart/columns`
is `required`** on the offscreen host, its `package` still A18, after three passes on each
target. A later `strata-rune` hands its launch to the running one, which opens a second window
sharing the process's one settings store (`settings::Saved::share`). A change made in either
window reaches the other through `shell::follow_another_window`, which reads the values again
and follows the look, the live preferences, the default sort, the freshness input and the item
colours. A part of the Settings window that keeps a copy of a setting beyond what it reads at
use follows another window only if that function makes it.
