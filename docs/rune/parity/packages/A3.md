## What dependents must know

- **The sidebar's keys start with `sidebar`:** the list `sidebar-list`, a row
  `sidebar-place-<id>`, `sidebar-pin-<n>` or `sidebar-device-<id>`, the Trash's icon
  `sidebar-trash-icon`. `Situation::within("sidebar")` is true inside it. A pin's id is its
  index, from 0, among the pins the store parsed from the bookmarks file, which skips blank,
  unreadable and repeated lines (`parse_pinned_places` in
  `crates/strata-fs/src/adapters/bookmarks.rs`): not its line in the file.
- **`slots::Sidebar::focus` is a function of the state** (`contract`): the key that takes
  the keyboard from the view as the sidebar is now, or None while it can take none. The
  sidebar answers with the open place's row, else its list's first row, as GTK's
  `focus_active_place` does, and None while it is hidden, so Left leaves the keyboard in the
  view.
- **C8 drags its own rows to reorder** (`contract`): `PlacesSidebar::reorder(on)` turns it on,
  `SidebarState::places_reorder` and `pins_reorder` are `RowDrag`s, and a move reaches the host
  as `MovePlace` or `MovePin` on the release, with its `Tx`. `take_reordered` is gone.
- **The QA backend presents the sidebar's pin gaps** as groups named "PINNED"
  (`crates/strata-app/src/qa/sidebar.rs`), from the elements C8 keys `sidebar-gap-<i>`.
- **The view keeps its place in the tree whether a sidebar is there or not**
  (`shell::body`, `contract`): `body` → `body-beside` → `body-files` → the view.
- **The header's actions are named by a `shell::Face`** (`contract`): a name, a tooltip that is
  also the description where it differs from the name, and a toggle's pressed state, built at
  each run of the view so a rebinding shows at once. A part whose command a header button runs
  and that owns how it is named (A3's toggle, through `sidebar::toggle_face`) gives the face; a
  new header action takes `buttons::on_return` as the others do.
- **`toggle-sidebar` is registered** (Ctrl+B, the header's button): a run that needs the
  sidebar railed or hidden can step it.
- **The sidebar acts on no drop and opens no menu yet:** its `PinHover`, `PinDrop`,
  `DropInto`, `DropHover` and `ContextMenu` intents are heard and dropped.

## Open

- **A known difference of the QA presentation, by the coordinator's ruling:** GTK exposes
  each pin gap to assistive technology as an empty group named "PINNED"; Rune keeps them out
  of the tree, as C8 decided, and only the QA backend presents them.
- **A dragged row's lost release:** rune-kit's `Reorder` let go of a held row when the pointer
  moved with no button down (its `on_pointer_move_local` on every row). C8's drag forgets it at
  the next press, or when the sidebar lists its rows again, so a row whose release never came
  stays drawn lifted until then.
- **The sidebar's arrows out of it** (GTK's `sidebar_navigation`: Right back to the files, Up
  to the header) and **its Menu key** are B3's FocusNavigation, deferred to this package, to
  build after the sidebar part; only 10xer `h`, Left and Backspace leave it today.
- **The keyboard when the toggle hides the sidebar:** with a sidebar row focused, Ctrl+B to
  the hidden step drops the row, and Rune leaves the keyboard on nothing. GTK hides the sidebar
  at the end of its animation and moves no focus itself; where GTK 4 then puts it (on nothing,
  or on the next widget, the files) was not checked against the oracle. If it is the files,
  the step gives the keyboard to `shell::view_focus` when `Situation::within("sidebar")`.
- **The toggle's role in the QA backend:** GTK's toggle is a toggle button (AT-SPI
  `toggle button`). Rune's is a button with a pressed state, as C9's and the footer's toggles
  are, which AccessKit already hands AT-SPI as a toggle button (`Role::Button` with `toggled`,
  in `accesskit_atspi_common`); only the QA backend's role table (`qa/roles.rs`), which reads
  the role alone, reports it as `button`. A scenario that selects it by role `toggle button`
  (`chooser-divider-keeps-marquee`, the chooser's) would not find it. A follow-up: map a
  button with a pressed state to `toggle button` there, checked against the runs that select
  C9's and the footer's toggles.
- **Search in 10xer mode:** GTK hides the header's Search button there
  (`tenxer_mode::hide_while_enabled`); this interface still shows it. The search package's.
- **Not yet ported:** the sidebar's menus,
  devices, the full Trash's icon, the `g` keycaps, middle-click into a new tab (no tabs on
  this interface), the automatic rail, the update notice, and the sidebar's saved width.
- **C8's headings and list name are English** (`Section::title`, "Places"), where GTK's are
  translated; the component carries user-facing text there. For a later `contract` change.
- **10xer activation** is [A11](A11.md)'s, and differs: GTK opens a row in 10xer mode with
  `emit_clicked()`, with nothing selected first, and hands the keyboard to the view once the
  location changes (`src/ui/window/keyboard/tenxer.rs:174-191`,
  `src/ui/window/keyboard/sidebar.rs:89`). C8's `l` opens with the first item selected, and the
  keyboard stays in the sidebar. Noted in A11's file.
- **Custom folder icons and colours** on places and pins (GTK's
  `customize_sidebar_folder_icon`, `src/ui/window/sidebar_rows.rs`): not drawn; every row has
  its default icon.
- **An unreadable bookmarks file, or a pin move that cannot be written:** GTK shows "Unable to
  update pinned folders" (`src/ui/window/bookmarks.rs:24-33`, `src/ui/window/sidebar_pins.rs:101-108`);
  this interface only logs both. [A5](A5.md)'s shared error dialog can show them.
- **Live settings:** GTK's sidebar rebuilds when `sidebar_order`, a place's visibility or a
  section's collapsed state changes (`bind_order` in `src/ui/window/sidebar.rs`), and its
  width when `sidebar_expanded` or `sidebar_compact` does (`bind_sidebar_modes`); this one
  reads them when the window starts, and changes only what it saves itself. Noted in
  [A18](A18.md)'s file, whose Settings page changes them.
- **Recent's second condition:** GTK also asks its `gtk-recent-files-enabled` setting, which
  this interface does not read, so it counts as on, its default.

## Notes from other packages

From [B1](B1.md) (2026-11-12):

- The sidebar's place is `Place::Sidebar(Sidebar { build, focus })`. A view whose keyboard
  leaves it at its start calls `shell::leave_view_at_start(app, tx)`, and the shell focuses
  the sidebar's `focus` key; the way back is `tx.focus(key, …)` with `shell::view_focus(app)`.
  `shell/tests.rs` has both directions with a made-up sidebar. A3 edits neither the Columns
  module nor the shell for this.
- One line of `slots.rs` is A3's to delete: the `expect(dead_code)` line on
  `Place::Sidebar`. Registering the sidebar makes clippy fail until that line, and only that
  line, is gone.
- Volumes and places come from services other than `Browser`: take `Setup::later` in
  `Part::new`, keep it in the sidebar's state, and queue with `later.then(…)` from a
  service's callback. A worker thread's result comes back through GLib and queues from
  there. Do not drain a queue of the sidebar's own in `Part::poll`.
- The header's Toggle sidebar button and the sidebar's key wait on [B3](B3.md).

From [B2](B2.md) (2026-11-12):

- Saving the sidebar's mode no longer waits: a part changes a setting with
  `shell::saved(app).change(|settings| …)` (merged in [#2178](https://github.com/lgse/strata/pull/2178)). The mode is a plain field of
  `Preferences`, so no setter moves.
- A guard GTK has and the Rune side lacks, which cannot fire today:
  `PreferenceManager::set_sort_preferences` stores nothing when handed a recency sort, and
  `Saved::store_view` has no such guard. Neither interface is ever handed one, because
  `Browser::record_sort` returns early at the Recent root. If that changes, the guard is one
  line in `store_view`, with a test that can fail.

From [H1](H1.md): `letter_bookmarks` stays with A3 although its three runs need 10xer mode,
a default for the owner to confirm ([`owner.md`](../owner.md#h1-whole-corpus-ledger)).

From [A5](A5.md) (2026-11-13, [#2286](https://github.com/lgse/strata/pull/2286)): **a press
in the sidebar while the location is edited keeps its focus.** The location bar cancels an
edit whose entry lost the keyboard to a press elsewhere, a frame later, and then leaves the
keyboard where that press put it, as GTK's capture-phase cancel does
(`install_location_cancellation`, `src/ui/window/composition/input.rs`): it gives it back to
the view only when nothing has it (`route_ticked` in `crates/strata-app/src/location/intents.rs`).
So a sidebar place clicked mid-edit keeps the keyboard once the sidebar takes focus on a press.
