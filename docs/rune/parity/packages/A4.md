## What dependents must know

- **`commands::On::Place(Location)`** is how a command is asked to act on a location that is
  no row of the view, or on a folder row's middle click: a sidebar row, a crumb, a view's
  folder row. A command that cannot act on one declines it.
  The sidebar's menu runs each of its rows but Unpin through `commands::run` on the row's
  location, so a part lights "Customize…", "Connect to server…" or "Properties" by
  registering the command named for it ([A6](A6.md), [A17](A17.md)), with nothing to edit in
  `sidebar/menu.rs`.
- **`open-in-tab` and `open-in-window`** are the names a new tab and a new window are asked
  for, from the sidebar, the crumbs, a view's folder row on middle click (`columns`, `single`)
  and the entry menu's rows (`menus.rs`). This package registers `open-in-tab`
  (`tab_strip/open.rs`), with Ctrl+Enter from the listing. No package registers
  `open-in-window` yet: it waits on a part that opens a second window, and with it Shift+Enter,
  which today opens in place as Enter does, and Ctrl/Shift+middle click on a crumb or a folder
  row.
- **Each tab has a browser and a state of each part of its own** (`crates/strata-app/src/shell/tabs.rs`).
  A part's `app.<field>` is the shown tab's; nothing names a tab to reach it. A value a part
  copies from the settings in `Part::new` does not follow another tab's change: read the
  setting at the call, or read it again in `Part::tab_shown`. What does not outlast a tab (an
  edit, suggestions, a popover) ends in `Part::tab_hidden`. A part the window keeps one of
  says `const SCOPE: Scope = Scope::Window` and follows the tab shown in `Part::tab_shown`.
- **A hidden tab runs nothing.** Its browser's events and its parts' services' answers wait for
  it; one that must act at once for a hidden tab cannot yet (the undo deferral above).
- **The QA backend watches every tab's browser for replaced rows** (`qa/replaced.rs`), from
  the first step after a tab opens, and asks the shown tab's.
- **The window closes through `shell::close_window`**, never `Csd::close` alone: it keeps
  GTK's close guard, which refuses while any tab has a file operation running. A part that
  starts a background operation (the progress dock's) needs nothing more.
- **A tab's name is `shell::tabs::label`**, and `shell::tabs::located` its location, or the
  one it waits on: the window title and the strip both read them.
- **The tab strip is `crate::tab_strip`.** `select`, `new_tab`, `open_in_new_tab`, `close` and
  `reopen` are the window's tab actions, for a part that opens or shows a tab (10xer's `t` chords, A11). The
  commands are `tab-new`, `tab-close`, `tab-reopen`, `tab-next`, `tab-previous`,
  `tab-move-left`, `tab-move-right` and `tab-number`. A part that ends something before its
  tab is hidden does it in `Part::tab_hidden`; the strip commits an open rename itself.
- **The modifiers held down are `shell::held_modifiers`**, one set for the window, none while
  it has no keyboard focus: for a part that shows more while a modifier is held, read while it
  builds, never as a command, so a modal layer that cuts a stage does not hide it. On the
  offscreen host they are heard as each step feeds them, ahead of the keys queued with them,
  so a key handler reads the key's own `mods`, not this. A test that feeds Rune
  `PhysicalInput::Modifiers` itself goes through `Offscreen::modifiers` for a part to hear it.
- **A hidden tab keeps the keyboard only where a pane's part keys it** (`Registry::in_panes`):
  an element of the shown view, the sidebar or the drawer whose key starts with its part's
  registered name. A part whose elements take the keyboard keeps to the rule in `slots.rs`,
  "Element keys are one namespace", or its tab comes back with the keyboard in its view.
- **Tab-strip and header New tab drop seams** (`crates/strata-app/src/tab_strip.rs`,
  `tab_strip/drops.rs`, `crates/strata-app/src/transfer.rs`):
  - `tab_strip::set_dnd(app, dnd)` swaps the `Dnd<App>` binder that wraps `"header-new-tab"`
    (when one tab is open), `"tabs-new"`, `"tabs"`, and each tab's drop zone (defaulting to
    `Dnd::rune()`).
  - `tab_strip::set_open_drag(app, Some(TabOpen::AtGap | TabOpen::AtEnd))` marks an active
    in-process folder drag (`Some(TabOpen::AtGap)` for a sidebar location drag, `Some(TabOpen::AtEnd)`
    for a folder-only view selection drag, `None` when the drag ends or carries a file). Call
    `set_open_drag(app, None)` on drag end so any open incoming tab gap clears too.
  - `transfer::start_drop_transfer(app, destination, sources, move_sources)` starts a drop
    transfer honouring `open_folder_after_drop`.
- **Tab sessions (`crates/strata-app/src/launch.rs`, `crates/strata-app/src/shell/tabs/session.rs`)**:
  `launch::Initial::Plain` marks the one plain-launch window that restores and persists
  `tabs.toml`, with `tabs_session::load_restorable()` called at start-up before the window opens;
  folder arguments, reveal requests, unlock flows and secondary windows use
  `launch::Initial::Explicit` so they neither restore nor overwrite `tabs.toml` ([A21](A21.md)).
  `shell::saved(app).change(|p| p.restore_tabs = false)` removes `tabs.toml` immediately, so
  Settings needs no extra call when toggling "Restore open tabs on startup" ([A18](A18.md)).
