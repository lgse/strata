## What dependents must know

- **`commands::On::Place(Location)`** is how a command is asked to act on a location that is
  no row of the view, or on a folder row's middle click: a sidebar row, a crumb, a view's
  folder row. A command that cannot act on one declines it.
  The sidebar's menu runs each of its rows but Unpin through `commands::run` on the row's
  location, so a part lights "Customize…", "Connect to server…" or "Properties" by
  registering the command named for it ([A6](A6.md), [A17](A17.md)), with nothing to edit in
  `sidebar/menu.rs`.
- **`open-in-tab` and `open-in-window`** are the names a new tab and a new window are asked
  for, from the sidebar, the crumbs, a view's folder row on middle click (`columns`, `single`)
  and the entry menu's rows (`menus.rs`). This package registers `open-in-tab`
  (`tab_strip/open.rs`), with Ctrl+Enter from the listing. No package registers
  `open-in-window` yet: it waits on a part that opens a second window, and with it Shift+Enter,
  which today opens in place as Enter does, and Ctrl/Shift+middle click on a crumb or a folder
  row.
- **Each tab has a browser and a state of each part of its own** (`crates/strata-app/src/shell/tabs.rs`).
  A part's `app.<field>` is the shown tab's; nothing names a tab to reach it. A value a part
  copies from the settings in `Part::new` does not follow another tab's change: read the
  setting at the call, or read it again in `Part::tab_shown`. What does not outlast a tab (an
  edit, suggestions, a popover) ends in `Part::tab_hidden`. A part the window keeps one of
  says `const SCOPE: Scope = Scope::Window` and follows the tab shown in `Part::tab_shown`.
- **A hidden tab runs nothing.** Its browser's events and its parts' services' answers wait for
  it; one that must act at once for a hidden tab cannot yet (the undo deferral above).
- **The QA backend watches every tab's browser for replaced rows** (`qa/replaced.rs`), from
  the first step after a tab opens, and asks the shown tab's.
- **The window closes through `shell::close_window`**, never `Csd::close` alone: it keeps
  GTK's close guard, which refuses while any tab has a file operation running. A part that
  starts a background operation (the progress dock's) needs nothing more.
- **A tab's name is `shell::tabs::label`**, and `shell::tabs::located` its location, or the
  one it waits on: the window title and the strip both read them.
- **The tab strip is `crate::tab_strip`.** `select`, `new_tab`, `open_in_new_tab`, `close` and
  `reopen` are the window's tab actions, for a part that opens or shows a tab (10xer's `t` chords, A11). The
  commands are `tab-new`, `tab-close`, `tab-reopen`, `tab-next`, `tab-previous`,
  `tab-move-left`, `tab-move-right` and `tab-number`. A part that ends something before its
  tab is hidden does it in `Part::tab_hidden`; the strip commits an open rename itself.
- **The modifiers held down are `shell::held_modifiers`**, one set for the window, none while
  it has no keyboard focus: for a part that shows more while a modifier is held, read while it
  builds, never as a command, so a modal layer that cuts a stage does not hide it. On the
  offscreen host they are heard as each step feeds them, ahead of the keys queued with them,
  so a key handler reads the key's own `mods`, not this. A test that feeds Rune
  `PhysicalInput::Modifiers` itself goes through `Offscreen::modifiers` for a part to hear it.
- **A hidden tab keeps the keyboard only where a pane's part keys it** (`Registry::in_panes`):
  an element of the shown view, the sidebar or the drawer whose key starts with its part's
  registered name. A part whose elements take the keyboard keeps to the rule in `slots.rs`,
  "Element keys are one namespace", or its tab comes back with the keyboard in its view.

## Notes from other packages

From [B1](B1.md) (2026-11-12): **the shell has one `Browser` and one state for each part,
and tabs need more.** In the GTK window each tab carries its own header and `Browser`; in
`strata-app`, `App` has one `browser` and each part's state is built once. So A4 opens with a
`contract` change that settles either a state for each tab or one browser replaced under
every part with a way to tell each part to rebuild. The other parts are held to what keeps
both open: no part keeps an `Rc<Browser>` of its own, each reads `app.browser` at the call,
and each can build what it shows again from the browser. The header's New tab button and
Ctrl+T wait on [B3](B3.md), whose seam must allow GTK's move of New tab and Close into the
tab strip when there is more than one tab.

From [B2](B2.md) (2026-11-12): the tab session store is `strata_desktop::tabs_session`
([#2170](https://github.com/lgse/strata/pull/2170)): `load_restorable()` at start-up only, since it reads the file and blocks; `save` and
`remove` queue on the shared settings writer and may be called from `poll` or an update.
The store holds locations and an index, no tab identity. The rules for using it live in GTK
code that is deleted at parity; they are listed in `docs/rune/shared-state.md`, "Tab
sessions": restore on a plain launch only, only one window persists its tabs, no save while
restoring, no save of an empty set, `remove()` while `restore_tabs` is off, a missing
folder's tab, the stored form being `main`'s to change, and the writer flushed at exit,
which the offscreen host does not do. **Session restore has no QA scenario**, so the ledger
holds A4 to none of these; that gap is [H5](H5.md)'s.

From [H1](H1.md): the three runs of `tenxer-tab-chords` are [A11](A11.md)'s.

From [B3](B3.md) (2026-11-12, [#2214](https://github.com/lgse/strata/pull/2214)): **under a modal layer the registry cuts the whole
`TabStrip` stage,** so no command registered there is asked while a part answers
`Holds::Modal`. GTK's tab strip blocks its commands there too, but it shows and hides the
tab-number hints before it asks whether it is blocked
(`src/ui/window/composition/tabs.rs:755-760`). The hints are therefore not a command at
that stage: the part that draws them reads the held modifiers for itself.

From [A7](A7.md) (2026-11-12, [#2272](https://github.com/lgse/strata/pull/2272)): **undo's
disk check is per window.** `Undo::checking` in `crates/strata-app/src/undo.rs` holds the
replays being checked for the one `Browser` there is; GTK keeps them per tab
(`preparing_transfers` on each `ViewState`). With tabs, the check is keyed by browser and its
answer goes to the browser that started it, not to `app.browser` at the time it lands.

From [A5](A5.md) (2026-11-13, [#2286](https://github.com/lgse/strata/pull/2286)): **the
location bar's state is per window, and wants one per tab.** `location::Bar` in
`crates/strata-app/src/location/` holds one `LocationBarState`, with its trail, for the one
`Browser` there is; GTK keeps a location entry and its completion on each tab's `ViewState`.
With tabs, each tab gets its own state and trail, and a tab hidden mid-edit calls
`LocationBarState::dismiss_completion` on its state, so its suggestions close and a listing in
flight is dropped (C6's "Switching tabs closes the previous tab's suggestions"). A crumb's
middle click asks for a new tab (`LocationIntent::OpenInNewTab`), which the bar only logs today.

From [A3](A3.md) (2026-11-13, [#2330](https://github.com/lgse/strata/pull/2330)): **the sidebar's context menus show "Open in New Tab" (id `open-in-tab`)
inert**, as GTK draws it, by the coordinator's ruling: the row's command is this package's
(GTK's `append_open_in_tab` in `src/ui/window/sidebar.rs`, left out in chooser mode). When this package wires it, the command needs the sidebar row's location, which
`commands::On` has no variant for: adding one (such as `On::Place(Location)`) is this
package's, a `contract` change, and the sidebar's menu then runs the row through
`commands::run` from `chosen` in `crates/strata-app/src/sidebar/menu.rs`, which today acts on
Unpin alone.

From [A8](A8.md) (2026-11-14, the #2427 and #2437 fixes): **`pane::Memory` holds one more thing,
the cursor a first visit placed** (`Memory::visit_cursor`, read and moved by
`single::first_visit::keep_on_first_row`). It belongs to the tab as the restore positions do,
so it travels with `pane::Memory` when the per-tab state takes it, with nothing more to move.
`shell::rebuild` now calls every active part's `caught_up` after a view's replay.

From [A6](A6.md) (2026-11-14, [#2461](https://github.com/lgse/strata/pull/2461)): **a modal layer ends the shown view's pointer gestures**
(finding [#2454](https://github.com/lgse/strata/issues/2454)). `shell::poll` ends with
`grab::follow` (`crates/strata-app/src/shell/grab.rs`): when a part starts answering
`Holds::Modal`, it calls `end_gestures` on `shell::shown_view(app)`, a new field of
`slots::View` that each view registration sets (Columns, Icons, List). It hangs off the shown
view, so with a state for each tab it is the shown tab's view whose gestures end; its flag is
the window's, not a tab's.
