## Notes from other packages

From [B1](B1.md) (2026-11-12): **the shell has one `Browser` and one state for each part,
and tabs need more.** In the GTK window each tab carries its own header and `Browser`; in
`strata-app`, `App` has one `browser` and each part's state is built once. So A4 opens with a
`contract` change that settles either a state for each tab or one browser replaced under
every part with a way to tell each part to rebuild. The other parts are held to what keeps
both open: no part keeps an `Rc<Browser>` of its own, each reads `app.browser` at the call,
and each can build what it shows again from the browser. The header's New tab button and
Ctrl+T wait on [B3](B3.md), whose seam must allow GTK's move of New tab and Close into the
tab strip when there is more than one tab.

From [B2](B2.md) (2026-11-12): the tab session store is `strata_desktop::tabs_session`
([#2170](https://github.com/lgse/strata/pull/2170)): `load_restorable()` at start-up only, since it reads the file and blocks; `save` and
`remove` queue on the shared settings writer and may be called from `poll` or an update.
The store holds locations and an index, no tab identity. The rules for using it live in GTK
code that is deleted at parity; they are listed in `docs/rune/shared-state.md`, "Tab
sessions": restore on a plain launch only, only one window persists its tabs, no save while
restoring, no save of an empty set, `remove()` while `restore_tabs` is off, a missing
folder's tab, the stored form being `main`'s to change, and the writer flushed at exit,
which the offscreen host does not do. **Session restore has no QA scenario**, so the ledger
holds A4 to none of these; that gap is [H5](H5.md)'s.

From [H1](H1.md): the three runs of `tenxer-tab-chords` are [A11](A11.md)'s.

From [B3](B3.md) (2026-11-12, [#2214](https://github.com/lgse/strata/pull/2214)): **under a modal layer the registry cuts the whole
`TabStrip` stage,** so no command registered there is asked while a part answers
`Holds::Modal`. GTK's tab strip blocks its commands there too, but it shows and hides the
tab-number hints before it asks whether it is blocked
(`src/ui/window/composition/tabs.rs:755-760`). The hints are therefore not a command at
that stage: the part that draws them reads the held modifiers for itself.
