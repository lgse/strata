## Plan

The package's agent planned it this way after its survey (2026-11-13), approved by the
coordinator with its rulings that day:

1. **The differential mode** (`contract`, the full gate), with the `--keep` fix folded in so
   that the gate is paid once.
2. **The pilot alphabet, `columns v1`**, Columns on the canonical fixture with type to search
   off: navigation, selection and rename, the rename editor's own keys included. Data and its
   pin, not `contract`. Its first differential smoke tier, and the triage of each difference
   class: 24 GTK replays, a shrink, a minimal repro, then a finding with its reference issue
   or a known owner question.
3. **Small Rune bugs in Columns navigation, selection or rename**, one pull request per class,
   with the shrunk sequence as a regression check where the fuzzer allows it. A class in
   another package's area is recorded as that package's finding, with a note in its file. A
   big or unclear class goes back to the coordinator first.
4. **The smoke budget**, set from the differential mode's own timings, and this file `done`.

The comparison keeps the map empty unless the owner rules: a divergence the alphabet cannot
guard is parked against its finding, never normalised. Up from a column's first row is
guarded by name, as A1's Left guard is, with its gaps accepted and reported; there is no
`first` predicate.

## What dependents must know

- **Run the smoke tier on both targets in one command,** `--target gtk,rune`: it costs what
  the two one-target runs cost, and it is the only one that compares GTK with Rune. Until the
  budget record lands, the area packages' smoke tier is unchanged.
- A `DIFFER` line now says which replays it compares: `on gtk`, `on rune` or `gtk against
  rune`, GTK's value first.
- **The views that restore a folder's position** (List and Icons, [A1](A1.md) and [A2](A2.md)):
  C1's `Selection::restore` now keeps a remembered Shift anchor that is not the cursor, where it
  always put the anchor on the cursor. A range started before leaving a folder goes on from
  where it started on return, as the feature map's position restore says.

## Open

- **Tab in the rename editor**, which on GTK commits the rename and starts renaming the next
  item (`advance_rename`, `src/ui/browser/view_edit.rs:57`), is left out of `columns v3`: it
  goes into the alphabet's next version, with #2356's pull request or a later one, and its
  triage then.

- **The view parameter for an alphabet** (A2's note below) is deferred, by the
  coordinator's ruling of 2026-11-13. It would only merge `list` and `icons`, whose action
  lists are the same; the Columns pilot shares little with them, since Right and Left there
  open and leave columns. And it changes what a sequence is named, the name's parser, the
  corpus files and the pins: a `contract` change the pilot does not need. A later package can
  take it when a third single-pane alphabet would copy the list again.

## Notes from other packages

From [A2](A2.md) (2026-11-12, the List alphabet's pull request), by the coordinator's
ruling: **a view parameter for an alphabet, worth doing when F2 starts.** An alphabet's `header`
fixes one mode, and its pin hashes the header, so the List alphabet
(`tests/qa/fuzz/alphabets/list.toml`) and the Icons one [A1](A1.md) adds hold the same
action list twice, by construction (the Icons one adds Right and Left). One alphabet with a
view parameter (a seed naming its sequence with the alphabet's version and the view) would
end the copy.

Also met, for the differential mode: on GTK, Up from a List's first row takes the keyboard to
the pane header, where Return leaves the fixture; Rune keeps the keyboard in the list
([`owner.md`](../owner.md), A1 item 3). The first draft lost 84 of its 1,600 GTK replay steps
to it (seed `0x11` ran 3 of 40 steps, `0x12` 35). The alphabet's Return now runs only on the
walk's two folders and in the rename editor, so the walk stays inside the fixture on both
targets; GTK's header focus still differs from Rune after Up. A differential run compares
`app.focused` and `app.focused_pane` after Up from the first row, and will report it there
until the owner rules: a `deviation` rule in `normalisation.map` once ruled, or Rune taking
the header focus. Likewise, after F2, Return on a folder or the Menu key, GTK reports no
entry under the keyboard (`app.focused` null) until a key moves it, where Rune keeps it
([`owner.md`](../owner.md), A2 item 4).

The QA image has no default application for the fixture's files: Return on one opens
Strata's Open With chooser on GTK, which takes the keyboard, and nothing on Rune, which has
no chooser yet (no package names it). That is the environment's, not a fault; the List
alphabet keeps Return off files. A walk into the fixture's empty `archive` once looked like a
trap on GTK (Back and the parent key lost); it was not reproduced by hand, where both leave
the folder on GTK and on Rune, so it is recorded as observed in the walk only.

Finding [#2235](https://github.com/lgse/strata/issues/2235) (the Menu key with the cursor
scrolled out of view) is unreachable with this fixture, whose folders are never taller than
the view; on GTK it would show only as a rename of the wrong file.

From [A1](A1.md) (2026-11-12, [#2273](https://github.com/lgse/strata/pull/2273), the Icons
alphabet), for the differential mode:

- **Skips differ between targets.** In the smoke tier of `icons v1`, seeds 1 to 20, GTK
  skipped 680 steps and Rune 662. The likely cause is the focus guards reading GTK's states
  with no entry under the keyboard (after Return on a folder, the Menu key, or Up from the
  first row), where Rune keeps the entry ([`owner.md`](../owner.md), A2 item 4 and A1
  items 3 and 4). Not verified: the smoke tier compares each target only with itself.
- **The Left guard's one reachable gap.** Left and `h` run only from entries that are rarely

  `diagram.txt` leaves `photo.txt` first. Left there takes GTK's keyboard to the sidebar,

- **`--keep` keeps one target's artifacts.** `./scripts/qa-fuzz.sh run --keep` writes both
  targets to `target/qa-fuzz/<area>/`, so the second target's run wipes the first's. It
  should keep them per target, `target/qa-fuzz/<area>/<target>/…`. The driver is F2's.
