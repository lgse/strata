## Notes from other packages

From [A2](A2.md) (2026-11-12, the List alphabet's pull request), by the coordinator's
ruling: **a view parameter for an alphabet, worth doing when F2 starts.** An alphabet's `header`
fixes one mode, and its pin hashes the header, so the List alphabet
(`tests/qa/fuzz/alphabets/list.toml`) and the Icons one [A1](A1.md) adds hold the same
action list twice, by construction (the Icons one adds Right and Left). One alphabet with a
view parameter (a seed naming its sequence with the alphabet's version and the view) would
end the copy.

Also met, for the differential mode: on GTK, Up from a List's first row takes the keyboard to
the pane header, where Return leaves the fixture; Rune keeps the keyboard in the list
([`owner.md`](../owner.md), A1 item 3). The first draft lost 84 of its 1,600 GTK replay steps
to it (seed `0x11` ran 3 of 40 steps, `0x12` 35). The alphabet's Return now runs only on the
walk's two folders and in the rename editor, so the walk stays inside the fixture on both
targets; GTK's header focus still differs from Rune after Up. A differential run compares
`app.focused` and `app.focused_pane` after Up from the first row, and will report it there
until the owner rules: a `deviation` rule in `normalisation.map` once ruled, or Rune taking
the header focus. Likewise, after F2, Return on a folder or the Menu key, GTK reports no
entry under the keyboard (`app.focused` null) until a key moves it, where Rune keeps it
([`owner.md`](../owner.md), A2 item 4).

The QA image has no default application for the fixture's files: Return on one opens
Strata's Open With chooser on GTK, which takes the keyboard, and nothing on Rune, which has
no chooser yet (no package names it). That is the environment's, not a fault; the List
alphabet keeps Return off files. A walk into the fixture's empty `archive` once looked like a
trap on GTK (Back and the parent key lost); it was not reproduced by hand, where both leave
the folder on GTK and on Rune, so it is recorded as observed in the walk only.

Finding [#2235](https://github.com/lgse/strata/issues/2235) (the Menu key with the cursor
scrolled out of view) is unreachable with this fixture, whose folders are never taller than
the view; on GTK it would show only as a rename of the wrong file.
