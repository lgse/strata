What the plan says of this package elsewhere, quoted with the section it is in:

- **Verification method, "Differential fuzzing".** Compare. A difference outside the normalisation map is a divergence. So is a step one target refuses, a panic, or a critical.
- **Verification method, "Differential fuzzing".** Triage. Each divergence becomes one GitHub issue with one outcome from the table below.
- **Verification method, "Differential fuzzing".** Compare only at rest. Nothing is compared mid-animation. Timeouts are budgets, never assertions, which is how the `timing` exception applies to fuzzing.
- **Verification method, "Differential fuzzing".** One normalisation map. A single file of rules, each naming a snapshot field, an exception code and an issue. Its rule count is printed in every fuzz summary and reviewed at each wave gate.
- **Verification method, "Differential fuzzing".** Alphabets belong to areas. Each area package adds its alphabet with its first required runs. Columns navigation, selection and rename are the pilot (F2).
- **Verification method, the fuzz tier table.** Smoke: Before a package's pull request merges. Budget: The area's alphabet, short sequences. Set by F2's pilot.
- **Coordination, "Shared files".** The normalisation map: One rule per line, sorted by field. A pull request adds only its own rules.
- **Open questions, "Decided".** Fuzz budgets. Calibrated after work starts, from F2's pilot numbers.
