## Notes from other packages

From [A10](A10.md) (2026-11-13), by the coordinator's ruling: **opening a file is this
package's.** `Browser::open_location` raises `BrowserEvent::OpenRequested`, which nothing on
this interface handles yet: a filter result opened by one click, by Enter or by a double click
asks for it (`filtered-file-click-previews/columns-one-click`, line 13), as Return on a file
in any view does. GTK opens the default application, and with none its Open With chooser.

From [A6](A6.md) (2026-11-14, [#2443](https://github.com/lgse/strata/pull/2443)): **`dialogs_and_menus/submenu-arrows-return-to-parent`** (all three views) stops at
line 10: the entry menu's "Actions" submenu, the custom actions', is not mounted. After it the
run copies with the menu's Copy row and pastes with Ctrl+V ([A12](A12.md)'s, lines 50 and 57).
The rows keep `package = "A6"`; the package whose part lands last flips them, or tells A6.

From [A6](A6.md) (2026-11-14, #PR2A): **the selection menu's Open row waits for the open-with
lookup.** GTK's menu for several entries shows Open only once its lookup finds a default
application they share (`prepare_open_with` in `src/ui/browser/context_menu/open_with.rs`,
which also makes Open With… sensitive). This interface has no lookup, so `menus.rs` leaves the
row out of `several`, as GTK does when it finds none (finding
[#2358](https://github.com/lgse/strata/issues/2358)). When this package adds the lookup, it
puts the row back for a shared default.
