## What dependents must know

- **Terminal launching (`crates/strata-app/src/terminal.rs`):** `terminal` (`Ctrl+Alt+T`, folder menu `"Open in Terminal"`, folder entry menu `"Open in Terminal"`, `On::Place`) and `actions-terminal` (`ACTIONS_TERMINAL` in `Map::Default` at `Stage::DirectCommands`) are live. `terminal::open_focused_folder(app)` opens a terminal in the focused listing's folder and returns `false` when refused (`!terminal::can_open`), ready for [A11](A11.md)'s 10xer `;` -> `t` chord (`Can’t open a terminal here`). `terminal::spawn_reaped`, `terminal::Emulator`, and `terminal::no_terminal_message` are `pub(crate)` for background launcher reaping and `.sh` execution in `run.rs`.
- **Custom actions and Jobs (`crates/strata-app/src/custom_actions.rs`):** `CustomActions` (`Scope::Window`, `Place::Dialogs`) reads `$XDG_CONFIG_HOME/strata/actions` through `strata_fs`'s `ActionRegistry` and runs through its `JobService`. Matching actions fill the section `menus.rs` reserves at `Menu::custom_slot` (`MenuPlacement::Top` rows, then the `"Actions"` submenu), right before `provider_slot`, so custom actions and file providers never shift each other's index; an open menu refreshes live when the actions change. `"Run this action?"` is C15's `StrataDialog`. `CUSTOM_ACTION_1..=10` are bound in `Map::Default` at `Stage::DirectCommands`; for [A11](A11.md)'s `;` and `; .` chords, `custom_actions::{NumberedActions, numbered_actions, run_numbered}` give the matching actions for the selection or the folder and run one (confirming when its manifest asks). The footer's `Bar::jobs` is C16's Jobs dashboard (`custom_actions::jobs_el`), a plain popover named "Jobs" (the `#2405` rule in `tests/qa/fuzz/normalisation.map` now lists it).
- **QA backend:** `crates/strata-app/src/qa/submenus.rs` puts each open submenu surface under the row that opens it, so `app.menu` lists its rows right after their trigger, in GTK's order (finding [#2507](https://github.com/lgse/strata/issues/2507), fixed). `qa/jobs.rs` presents the Jobs footer button's text and each row's status as GTK's `label`s. `qa/roles.rs` reports the Open With search as GTK's `gtk::SearchEntry` does, role `entry`, so it is no `text` field (`app.field`, `editable_fields`), as on GTK.
- **`Ctrl+Alt+T` under an open context menu launches nothing,** as on GTK, whose popover menu keeps the key from the window's actions (`terminal::reaches_window_actions`).
- **Opening files and Open With (`crates/strata-app/src/open_with.rs`):** `OpenWith` (`Place::Dialogs`) handles `BrowserEvent::OpenRequested` (`launch::open_location_at` also accepts `Option<Duration>` for [A16](A16.md)'s timed media-player handoff via `command_line_at`), registers `"open-with"` (`OPEN_WITH` on `Map::Default` at `Stage::DirectCommands` and `Map::Tenxer` at `Stage::FileCommands`), updates open entry/folder context menus asynchronously (`open_with::prepare_menu` and `open_with::open_selection_default`), and exposes `open_with::menu::open_targets(app, tx, report)` for [A11](A11.md)'s 10xer `O` feedback banner.

## Notes from other packages

From [A10](A10.md) (2026-11-13), by the coordinator's ruling: **opening a file is this
package's.** `Browser::open_location` raises `BrowserEvent::OpenRequested`, which nothing on
this interface handles yet: a filter result opened by one click, by Enter or by a double click
asks for it (`filtered-file-click-previews/columns-one-click`, line 13), as Return on a file
in any view does. GTK opens the default application, and with none its Open With chooser.

From [A6](A6.md) (2026-11-14, [#2443](https://github.com/lgse/strata/pull/2443)): **`dialogs_and_menus/submenu-arrows-return-to-parent`** (all three views) stops at
line 10: the entry menu's "Actions" submenu, the custom actions', is not mounted. After it the
run copies with the menu's Copy row and pastes with Ctrl+V ([A12](A12.md)'s, lines 50 and 57).
The rows keep `package = "A6"`; the package whose part lands last flips them, or tells A6.

From [A6](A6.md) (2026-11-14, [#2446](https://github.com/lgse/strata/pull/2446)): **the selection menu's Open row waits for the open-with
lookup.** GTK's menu for several entries shows Open only once its lookup finds a default
application they share (`prepare_open_with` in `src/ui/browser/context_menu/open_with.rs`,
which also makes Open With… sensitive). This interface has no lookup, so `menus.rs` leaves the
row out of `several`, as GTK does when it finds none (finding
[#2358](https://github.com/lgse/strata/issues/2358)). When this package adds the lookup, it
puts the row back for a shared default.

From [A6](A6.md) (2026-11-14, [#2457](https://github.com/lgse/strata/pull/2457)): **one case of `OpenRequested` is A6's: a regular
executable.** `crates/strata-app/src/run.rs` hears the event and, when the location is a local
path to a regular file with an execute bit (read through links, as GIO's `query_info` reads it),
opens "Run this program?" (`confirm_run_program` in `src/ui/browser/desktop.rs`). Every other
file is still this package's to open. GTK asks only once `resolve_default_application` finds no
default application for the type, so when this package adds the lookup, it goes first, and the
executable case becomes its fallback: hand the location to `run.rs` where no application is
found, and drop `run.rs`'s own listener. Two more things are left to this package:
- **A shell script (`.sh`)** runs in a terminal on GTK (`program_command`). `run.rs` asks, and
  on Run starts nothing and shows "Unable to run program", "Unable to open terminal". This
  package replaces that with the terminal (`confirmed` in `run.rs`).
- **The menu's Run row** (`run`, `run::runs`) is A6's and stays so.

From [A9](A9.md) (2026-11-16): **three runs in `tests/qa/parity/pointer_intent.toml` (`tap-drag-waits-for-release/{columns,list,icons}-file`, `package = "A9"`) also wait on this package's `.desktop` `OpenRequested` launching.** After [A19](A19.md)'s view-row drag onto `archive` at line 9, lines 15–18 double-click and press `Return` on `todo.txt`, expecting `$XDG_DATA_HOME/applications/strata-tap.desktop` (`mimeapps.list`) to run and append to `launched.log`.

From [A13](A13.md) (2026-11-16, [#2536](https://github.com/lgse/strata/pull/2536)): **open `rune-kit` submenu QA nesting and `Menu::provider_slot` are already wired.** `crates/strata-app/src/qa/submenus.rs` (called from `Snapshot::read` in `qa/tree.rs`) reparents open `*-sub-menu` surfaces under their owning `menu` to match GTK's nested `GtkPopoverMenu` hierarchy. In `crates/strata-app/src/menus.rs`, `Opening::provider_slot` (`Menu::provider_slot`) marks the section index where file-provider sections splice after the open section (`if can_create { 3 } else { 1 }` on entries, `2` on folder menus); keep `provider_slot` aligned when inserting `MenuPlacement::Top` or `"Actions"` sections (and when `Send to…` lands for `Placement::SendTo`).
