## What dependents must know

- **Clipboard commands and query helpers (`crates/strata-app/src/clipboard.rs`):** `copy`, `cut`, `copy-path`, `copy-paths`, `copy-name`, and `copy-names` are live across all views. `clipboard::has_files(app)` reports whether file URIs are on the clipboard (including asynchronous verification of external Wayland offers so empty or comment-only URI lists do not light the badge), `clipboard::may_paste(app, location)` checks folder paste eligibility, and `clipboard::marks` / `clipboard::with_marks` supply `RowMarks { copied, cut }` to collection rows and tiles.
- **Footer clipboard badge (`crates/strata-app/src/footer.rs`):** C19's `Footer` receives `.clipboard(clipboard::has_files(app))` and `FooterLabels::{clipboard, clipboard_description}` matching GTK's `paste_label` (`"Files on clipboard"` and `"Press %{keys} to paste into a supported directory."`, or empty description when `PASTE` is unbound).
- **Paste, duplicate, and transfer progress (`crates/strata-app/src/transfer.rs`):** `paste` (`Ctrl+V`, folder menu) and `duplicate` (`Ctrl+D`, entry menu) run non-conflicting transfers and same-folder numbered copies end-to-end, hosting C16's `DockView` in `Slot::Overlays` and `ProgressDialog` in `Slot::Dialogs`, and revealing placed items via `BrowserEvent::TransferReveal`. Until Slice 4 mounts the conflict prompt, any paste batch where an item collides stops safely like Cancel (moving or copying nothing and keeping cut marks intact). Destination conflict prompts, foreign QA clipboard steps, undo replay collision prompts, and `New Folder with Selection` follow in Slices 3–5 above.
- **Shared message dialog variants (`crates/strata-app/src/error_dialog.rs`):** `Error::partial_failure(message)` (`Completed with errors` / `Some items could not be processed`, `IconName::Close`, `Tone::Danger`) and `Error::information(title, summary, message)` (`IconName::Info`, `Tone::Accent`) are available alongside `Error::new`.

From [A1](A1.md) (2026-11-12): **thumbnails do not wait for a running copy or move.** GTK
parks a file an operation holds and renders it on release (`HELD_FOR_OPERATION`,
`admit_after_release` in `src/ui/thumbnail/jobs.rs`). On the Rune side the render fails and
the tile keeps its icon until the row's key changes (the browser reads the finished file's
modification time and size) or the store's `retry_after` (30 s) passes. A run of this
package's that pastes images into a folder shown in Icons may see icons for up to 30 s where
GTK shows thumbnails at once. `A1.md`, "Open", has the detail.

From [A7](A7.md) (2026-11-12): **undo's replay asks no conflict prompt yet.** GTK prompts
when a move's undo or redo finds an item where it goes (`resolve_replay_collisions` in
`src/ui/browser/transfer/replay.rs`). `crates/strata-app/src/undo.rs` sorts the records as GTK
does and, where any collides, stops as the prompt's Cancel does: nothing moves and the entry
stays (`resume_move`). The prompt this package mounts for transfers is the one that goes
there, with GTK's Replace, Skip and Apply to All rules (`replay_prompt_visibility`,
`apply_replay_choice`); `undo.rs` is A7's, so the change is a note to A7 or a `contract`
pull request. `Sorted` keeps only a count of the collisions (`undo/replay.rs`): the prompt
needs their records and each one's kinds, as GTK's `ReplayCollision::between` builds them,
so `Sorted` grows those first.
