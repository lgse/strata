## What dependents must know

- **One drawer, shared viewer seam (`crates/strata-app/src/preview/`):** `Preview` is mounted once behind `Place::Drawer` in `crates/strata-app/src/lib.rs`. Do not mount a second `Place::Drawer` part (`slots::Registry` enforces at most one).
  - [A16](A16.md) (PDF, audio/video, 3D models, GPS routes) and [A13](A13.md) (archive trees and archive password prompts) plug in by adding variants to `preview::viewer::Viewer` (implementing `HostedPreview` where searchable/switchable) and dispatch arms in `preview::load::start` / `render_ready`.
  - Every focusable or keyed element inside a hosted viewer **must** use a key starting with `"preview-"` so tab-switch focus memory (`Registry::in_panes`), Space-to-close (`in_preview_outside_find`), `Ctrl+F` routing (`filter::ctrl_f`), and `!at.within("preview")` guards on `trash`/`delete`/`rename`/`copy`/`cut`/`paste`/`duplicate` (including unfocused pointer text selections via `Situation::within`) cover it automatically.
  - `--preview-helper` is dispatched in `crates/strata-app/src/launch.rs` before GTK/Rune initialization, so `strata-preview`'s `bwrap` sandbox helper (`current_exe() --preview-helper`) works out of the box for [A16](A16.md)'s PDF, model, and media thumbnail workers.
  - When [A16](A16.md) mounts `PdfView`, register its `Ctrl+0` zoom reset at `Stage::ZoomShortcut` ahead of `appearance`'s `text-reset` (see A8's note below).
- **What the preview follows (`crates/strata-app/src/preview/follow.rs`):** the `Browser` listener, and the hooks a view calls when it moves the keyboard or the target without moving the browser's cursor, where GTK's views raise `FocusChanged`: `follow_active_column` (`ColumnsIntent::Active`: Left, Right into an open column, a header or peek click), `note_click_opening` (a pointer activation of a folder in Columns, GTK's `TabLocationHold::opening`), `follow_filter_close` (`FilterIntent::Closed`) and `follow_filter_pick`. A view that moves focus on its own calls them rather than raising browser events.
- **The header keeps what the request carried**, as GTK's `show_identity` does: no refresh from the listing or `MetadataFilled`, so a filter's result or a just-listed file shows `—` for size and date on both toolkits.
- **What `preview_session/peek-click-reveals-column` proves.** Its Rune mutation patch blanks the
  peek targets' accessible name (`crates/strata-app/src/columns/view.rs`). Two behavioural mutants
  in `strata-app` survive the run: dropping `session::show`'s `reveal_active`, and dropping
  `Columns::publish`'s `set_active_column`, since the Columns component keeps the parent column
  in view and a later key publishes the active column again. The run checks what a peek click
  reveals and focuses, which is the component's; a run that catches those two is open for
  whoever owns the scenario's coverage.
- **Space inside the drawer** closes the preview only from the divider grip in default mode (header buttons and the body take it, as GTK's widgets do), and with `i` from anywhere in it in 10xer mode.

From [A7](A7.md) (2026-11-13): **the delete keys must wait while the preview has focus.**
GTK's `confirms_delete` refuses Delete and Shift+Delete while the preview has focus
(`src/ui/window/keyboard/items.rs`), as `inline_editing` refuses rename. Rune's `trash` and
`delete` commands (`crates/strata-app/src/trash.rs`) and `rename` (`rename.rs`) guard only
on `!at.text()`, since nothing mounts a preview yet. Whoever mounts the preview adds it to
those guards, with `Situation::within`.

From [A8](A8.md) (2026-11-13), found in the review of [#2349](https://github.com/lgse/strata/pull/2349):
**the Columns cap and the preview.** GTK caps a column at the browser's area, which takes in
the preview's slot, since the slot yields to the columns ("focused column, then preview, then
peek", `publish_column_width_limit` in `src/ui/preview/layout.rs`). The Rune side caps it at
the Columns view's own width (`crates/strata-app/src/columns/width.rs`), less what a railed
sidebar holds back. Once the drawer puts a preview beside the view, that width is narrower
than GTK's area, and so is the cap: the drawer should hand Columns the area with its slot
counted in.

From [A8](A8.md) (2026-11-13), found in the review of [#2352](https://github.com/lgse/strata/pull/2352):
**Ctrl+0 and a PDF's zoom.** GTK's `zoom_shortcut` first lets a focused PDF reset its zoom
(`preview.reset_pdf_zoom`, catalog `PDF_ZOOM_RESET`, Ctrl+0), and only then reads Ctrl+0 as the
text size's reset (`src/ui/window/keyboard.rs`). On the Rune side `text-reset` takes Ctrl+0 at
that stage (`crates/strata-app/src/appearance/text_size.rs`). Whoever mounts the PDF preview
([A16](A16.md)'s viewer in this drawer) registers its reset at `Stage::ZoomShortcut` ahead of
it, so Ctrl+0 in a focused PDF resets the PDF and leaves the text size.

From [A8](A8.md) (2026-11-13), by the coordinator's ruling 1 for A8: **the Appearance popover's
"Preview panel" runs `preview-panel`, which is this package's to register.** The row is a
`toggle button` named "Preview panel", described "Toggle preview panel while browsing
(Space)", and drawn unpressed (`crates/strata-app/src/appearance/popover.rs`). It runs the
command `preview-panel` by `commands::run` and closes the popover; until this package
registers the command the row is inert, as the header's buttons are. GTK's row is bound to
the drawer's stateful action `preview.preview-panel` (`src/ui/preview/drawer.rs`), pressed
while the drawer is enabled or reserves the column space (`src/ui/preview/session.rs`), and
toggles the panel for the selected entry. When the command lands, the row's pressed state
should follow the drawer: a `Face`-like read the popover can call, or the row reads it from
the part. Runs that toggle it and then check the drawer wait on this package.
