## Notes from other packages

From [B1](B1.md) (2026-11-12): **what the Rune QA backend still assumes of a view.** The
backend names no view: it reads the shown one through `shell::shown_view(app)` and its
`Probe` (`name`, the pane's mark; `roles`, Rune's roles of an entry list and an entry;
`lists`, the keys of the entry lists; `listed`, for `ready`). What `qa/tree.rs` and
`qa/stage.rs` still take for granted, and a second view may not satisfy: a pane is the
nearest named `group` above an entry list; a row behind an open menu is found by the
collection's `row-…` key and its name by the collection's `LABEL` key; and `qa/roles.rs`
maps only the Rune roles it lists to the scenarios' AT-SPI names, so a grid or a table needs
entries there.

**Ownership**, a default of the orchestrating session for the owner to confirm: `qa/` is
this package's. An area adds its own steps and predicates in files of its own; a view whose
panes do not fit does not edit `qa/` in passing, but opens a `contract` pull request agreed
with this package ([`owner.md`](../owner.md#b1-shell-seams)).

From [B2](B2.md) (2026-11-12): there are two readings of the US-QWERTY table for a press
with no physical origin, `src/ui/keys.rs` and `crates/strata-app/src/qa/keys.rs`. B2 puts
one in `strata_desktop::keys` and uses it on the GTK side; the copy in `strata-app` becomes
the shared one here or in [B3](B3.md), so the two QA backends read a synthetic press alike.

From the review of A1's pull request #2192 (2026-11-12), two follow-ups for the harness:

- **A per-patch selection for Rune mutation patches.** `scripts/qa_parity_mutation.py` takes
  only a target today, so proving one patch means applying it by hand. A selection by patch
  would let one be proven alone, as the plan's
  [When a mutation run is right](../README.md#when-a-mutation-run-is-right) asks.
- **The probe's view checked against the run's mode at start.** Seven Icons runs passed on
  Rune through the Columns fallback before an Icons view existed; a check at start that the
  shown view's probe matches the run's mode would have caught them.

From [A2](A2.md) (2026-11-12): **`qa/tree.rs` changed under contract.** `mark_column` marked
every node of the probe's entry role under an entry list as an entry. The List table's
headings are a `row` of its grid, as its entries are, so the backend read an entry named
`Name` in every List pane and each exact `entries` check failed. An entry is now a node of the
entry role keyed as the collection keys an entry's row (`collection::element::row_key`). The
slots docs said in part that rows are keyed so; the `Probe` docs in `slots.rs` now add that a
view's other rows (headings, group headers) must not take that key's form. The Columns and
Icons entries were keyed so already. Two unit tests in `qa/tree/tests.rs` hold it.

From [A2](A2.md) (2026-11-12): **the List headings' role differs.** GTK's List headings are
`gtk::Button`s (`src/ui/browser_modes/list_headings.rs:126`), and GTK scenarios aim at them as
`{"role":"button","name":"Size"}`: `view_switching/list-column-drag-applies-on-release`,
`view_switching/list-column-resize-tracks-pointer` and
`chooser_selection/chooser-heading-escape-keeps-selection`. On Rune the same heading is C4's
`column-header`, which `qa/roles.rs` presents as `column header`, so those steps find nothing.
A blanket remap of `column-header` is wrong: GTK uses `column header` for real column headers
elsewhere (`quick_preview/table-preview-keeps-secondary-sorts` clicks one in the preview). The
three answers: the backend presents the List table's headings as `button` (the plan's order of
resort, "absorb it in the backend"); C4's headings take the `button` role; or a ruling that
GTK's role is the oracle's fault. **Default in force, the orchestrating session's: the
first.** It is a `contract` change to `qa/` by whichever package first has a run that targets
a heading ([A2](A2.md) with its columns pull request, if that comes first).

From [A2](A2.md) (2026-11-12), by the coordinator's ruling on #2234: **a ledger that does not
parse.** A stray `\'` in `tests/qa/parity/keyboard_navigation.toml` did not pass unseen:
`qa_parity_check.parse` catches `TOMLDecodeError`, `qa_parity.load` raises it as `BadLedger`,
and `refuse` prints it on stderr and exits 2, for `qa-parity.sh A2 --counts` and for
`qa-parity.sh A2 --target rune` alike, with no traceback:
`keyboard_navigation.toml: Unescaped '\' in a string (at line 140, column 75)`. `mise run
scripts` failed too, since its tests read the committed ledger. A gate script that hid
stderr and ignored the exit status read it as a pass; that was the gate's fault, not the
harness's. What the harness lacks is a test of it: no case in `tests/qa/parity_cases.toml`
gives a reader a file that does not parse. One there (`refused` naming the parser's reason)
would hold the behaviour.

From [A1](A1.md) (2026-11-12): **the engine finds no viewport for a C1e collection**
([#2254](https://github.com/lgse/strata/issues/2254), `findings.md`). `locate::viewport` looks for a `scroll pane` among the
entry list's ancestors; every C1e collection holds its vertical scroll viewport inside the
list, so the Icons grid has none and `middle_visible` reads nothing
(`return-restores-nested-scroll/icons`, line 4). List reads C4's sideways viewport, an
ancestor, which is close enough for the middle-entry note but not for a `scroll_value`
check. The fix finds the collection's own viewport, a descendant of the entry list, instead
of the nearest ancestor.

From [A7](A7.md) (2026-11-13): **a `panel` inside a list item has no node on Rune.**
`rename_visibility/committed-rename-stays-visible` (line 14) and
`quick_preview/rendered-document-word-selection` target `{"role":"panel","within":{"role":"list
item",…}}`, the box a GTK row draws its content in, to check it is inside the pane. Rune's row
has its label and no box, so the engine finds nothing ("not on screen") though the row is
selected and shown whole. Whether the backend presents the row's own box as that panel, or the
run takes an `a11y` twin, is this package's call.

From [A3](A3.md) (2026-11-13), `contract`, the reordering pull request: **a hook in the
backend for the sidebar's pin gaps.** `qa/sidebar.rs` (A3's) reads the elements C8 keys
`sidebar-gap-<i>` and presents each as a group named "PINNED" under the window, as GTK's gaps
are. The hook: one field on `Drawn` (`sidebar: super::sidebar::Gaps`, filled in `stage.rs`'s
`drawn()`), one call in `Snapshot::read` (`drawn.sidebar.present(&mut snapshot)`), and
`Snapshot::push_under_window`, a node a part draws and the tree leaves out. `tree/tests.rs`'s
`Drawn` literals take `..Drawn::default()`.
