## Notes from other packages

- **Where thumbnails are** (from [A1](A1.md), 2026-11-12):
  - The window's decoded thumbnails are one C25 `ThumbnailStore` in the shell: `shell::thumbnails(app)` to read, `app.window.thumbnails_mut()` from a handler. The render pool is per process in `crates/strata-app/src/thumbnails/`.
  - A view that draws thumbnails keeps a `thumbnails::Viewer` (made with its part's `Setup::later`), calls `Viewer::pump(app, parts, resolve, clock)` from its `poll`, and gives its component `(store, viewer.id())`. `parts` borrows its `Viewer` and the store together; `resolve` finds an entry's file through the browser, as `icons/part.rs`'s `entry_file` does.
  - `listing::Row` carries each entry's `ThumbKey` (`Entry::thumbnail`), so a view built on `listing.rs` gets the keys with no work of its own.
  - GTK's List rows draw an 18 px thumbnail in the icon column (`src/ui/browser_modes/list_factory.rs`, `ThumbnailSlot` and `request_thumbnail_and_metadata`). The List view's icon slot reads the same store through its own viewer.
- **A row's facts, and their text** (from [A1](A1.md), 2026-11-12, by the orchestrating session's ruling):
  - `listing::Row::facts()` gives a `listing::Facts`: `size` (`Option<u64>`, bytes), `child_count` (`Option<u64>`), `duration_seconds` (`Option<u64>`) and `dimensions` (`Option<(u32, u32)>`, pixels), copied from the browser's `FileEntry`. Each is `None` until the browser knows it. The native listing leaves sizes unknown until a metadata fill, as GTK's does. No strings.
  - The text is `crate::details`, shared by both views. List's size column reads `size` through `strata_core::i18n::file_size`, GTK's `format_file_size`, and a folder's count through `details::items` ("No items", or the plural of "items"), as GTK's `entry_size` does. Do not add a second copy. A `size_column` function beside `details::icons_line` is the place for `entry_size`'s rule when List needs it.
  - Modified time and type are not in `Facts`. A2 adds what its other columns need in its own `contract` change, beside these.
  - **Metadata fills are shared** (from [A1](A1.md)'s fills pull request): `crates/strata-app/src/fills.rs`. List keeps a `Fills::new(false)` (GTK's List asks without the icon details: `metadata_fill_position(…, true, false)` in `list_factory.rs`), records the range from its collection's `on_visible` with `Fills::see` and nothing else there, and calls `Fills::request(&app.browser, depth, listing)` once from its part's `poll`, as `icons/part.rs`'s `fill` does. The margin, the once-a-poll batch, the one `prioritize_metadata_fills`, the skip of a folder an operation touches and the once-while-in-flight rule are in the module.
  - **A thumbnail viewer takes a `locate`** now: `thumbnails::Viewer::new(later, locate)`, with `locate(app, id)` giving the entry's depth and position in the browser; `Viewer::pump(app, parts, clock)` no longer takes a `resolve`.


From [B1](B1.md), on what a view is in `crates/strata-app/src/slots.rs` (2026-11-12). Nothing
here is this package's to change in passing: a file another package owns changes in a
`contract` pull request of its own.

- **What a view writes:** a module with its state, `impl Part` for it, and its two lines in
  `lib.rs` under its package's comment. Its place is `Place::View(View { build, shows,
  focus, pointer_at, rows, editing, probe })`. `columns/part.rs` is the worked example and
  `test_support::idle_view` a view whose every call does nothing.
- **`shows`** says whether the view is the one the saved `browser_mode` names. The GTK
  application also reads `explorer` as List, and that reading has not moved, so the List
  view's `shows` answers to both `list` and `explorer`.
- **The listing is shared:** `listing.rs` and `events.rs` belong to the contract. A view's
  listener calls `events::read` and applies each `Change` to its own component's state.
- **`columns/`** has no area package. If a second view needs part of it, [A1](A1.md) opens
  that `contract` change and A2 waits for it.
- **`rows`** is all the context menu asks of a view; what a chosen row does is decided once,
  in `menus::chosen`. **`editing`** is what the rename editor asks; a view without a
  follower gives `None` for `hold` and `follow_now`.
- **The keyboard:** `focus` is the key that takes it back from a field or a menu; where the
  keyboard leaves the view at its start, the view calls `shell::leave_view_at_start`.
- **`probe`** tells the QA backend how to read the view's panes. If they do not fit, or
  `qa/roles.rs` has to learn a role, that is a `contract` change with [H3](H3.md).
- A view is chosen once, from the saved mode; a live switch is [A8](A8.md)'s.
  `test_support::hosted_over` tests a place without registering it.

## What dependents must know

- **The List part is `crates/strata-app/src/list/`**, on the shared `Pane`, keyed `list`:
  the table's collection, the element that takes the keyboard, and the start of every
  element key the part makes. The pane around it is the group `list-pane`, named by the
  folder and described "List view"; the table is named by the folder and described "Files".
- **The Icons and List views share `crates/strata-app/src/single/`** (the contract's):
  what both do with their pane is written there once, and a change to it reaches both. A
  view's own module holds its component, keys, probe roles and words.
  What comes next attaches once there: `menus::open` in `heard`'s `ContextMenu` arm,
  [B3](B3.md)'s `commands::in_view` on `single::collection`, and anything more for `Pane::new`
  through `Single::new`, whose fifth parameter would make its parameters a struct.
- **The QA backend reads it with the probe `("grid", "row")`, named `List`.** The headings
  are a `row` of the grid too; since #2206 the backend takes only rows keyed as entries for
  entries. A heading is a `column header` on Rune where GTK has a `button` ([H3](H3.md)).
- **The table shows the Name column alone** until the listing carries what Mode, Size, Type
  and Modified show. A package that needs a column (A10's sort headings, A8's "Customize
  columns…") waits for that pull request.
