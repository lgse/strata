# Guided manual test plan — PR #740

## Pull request

| Field | Value |
| --- | --- |
| URL | https://github.com/lgse/strata/pull/740 |
| Title | `fix(model): percent-decode display names of remote locations` |
| Base | `lgse/strata` `main` |
| Head branch | `fix/658-uri-display-name-decoding` on `wmfeht/strata` |

| Linked issue | https://github.com/lgse/strata/issues/658 |
| Draft | yes (leave draft; this plan does not merge or mark ready) |

`Location::display_name` for URI locations used the raw last URI segment. Column headings, Icons/List pane titles, breadcrumbs, peek headings, transfer conflict names, folder Properties titles, accessibility pane labels, and pinned-place labels (when a bookmark line has no label) showed `My%20Share` for an SMB/SFTP folder named “My Share”. This PR derives the URI display name from GIO’s decoded basename (`file_name()`), and keeps the old last-segment split only when that basename is missing (roots such as `sftp://host/`). Native `display_name` and all of `display_path` are unchanged.

## How cases were selected

Cases follow the #658 report, the PR description, the diff (`src/model/mod.rs`, `src/model/tests.rs`), and the review/QA comments on the PR (no GitHub review threads; discussion is in PR comments).

Included:

- The reported heading regression (space and UTF-8) and the committed root-fallback example.
- Every production call site of `Location::display_name()` that can show a remote folder name: Columns heading, Icons/List pane title, breadcrumbs, peek heading, folder Properties (empty-pane Properties), transfer conflict copy, pinned-place label fallback, accessibility pane/list names.
- Contrasts the review/QA notes called out: native literal `%20`, `display_path` / location bar / heading tooltip still encoded, Trash still “Trash”, listing rows already decoded via GIO, one-pass decode.
- A second-window check because headings rebuild from the same helper.

Omitted on purpose:

- Live credential-in-URI window titles (`sftp://user:secret@host/` fallback). Review marked that pre-existing and out of scope for #658. Do not put passwords in location URIs.
- Query-string, malformed `%`, and `%2F` URI probes that need no mount. Those are API-level; the PR already has a focused unit test. Re-running that test is TP-01. Do not paste tokens into the location bar.
- Full Rust/E2E suites (CI owns those). `file://` in the location bar is rejected (`UnsupportedScheme`); it is not a UI stand-in for this bug.

If a live SMB/SFTP mount cannot be created, mark TP-02–TP-13 and TP-15–TP-16 **BLOCKED**, still run TP-01, TP-14, TP-17, and TP-18, and record the mount error in Actual (no secrets).

## Shared fixture (isolated / disposable)

Use a throwaway directory and a throwaway SFTP daemon. Do not use a personal home folder, production shares, or saved passwords. Do not record usernames, private paths, keys, or tokens in the Results table.

### 1. Disposable directories

```bash
FIXTURE="$(mktemp -d "${TMPDIR:-/tmp}/strata-740.XXXXXX")"
mkdir -p "$FIXTURE/remote/My Share/Sub Dir" \
         "$FIXTURE/remote/café" \
         "$FIXTURE/remote/My%20Share" \
         "$FIXTURE/native/My%20Share" \
         "$FIXTURE/dest/My Share" \
         "$FIXTURE/config" "$FIXTURE/cache" "$FIXTURE/data" "$FIXTURE/ssh"
printf 'notes\n' > "$FIXTURE/remote/My Share/notes.txt"
printf 'notes\n' > "$FIXTURE/dest/My Share/notes.txt"
printf 'native\n' > "$FIXTURE/native/My%20Share/file.txt"
```

`$FIXTURE/remote/My%20Share` is a folder whose **real** name is the six characters `My%20Share` (percent, two, zero). `$FIXTURE/native/My%20Share` is the same name on a native path.

### 2. Throwaway SFTP (key auth only)

Generate keys **in the fixture directory**. Do not reuse personal keys. Do not paste private keys or passwords into this document or into results.

```bash
ssh-keygen -t ed25519 -f "$FIXTURE/ssh/host" -N '' -C 'strata-740-host'
ssh-keygen -t ed25519 -f "$FIXTURE/ssh/id" -N '' -C 'strata-740-client'
PORT=2222
cat > "$FIXTURE/ssh/sshd_config" <<EOF
Port $PORT
ListenAddress 127.0.0.1
HostKey $FIXTURE/ssh/host
PidFile $FIXTURE/ssh/sshd.pid
UsePAM no
PasswordAuthentication no
KbdInteractiveAuthentication no
PubkeyAuthentication yes
AuthorizedKeysFile $FIXTURE/ssh/id.pub
StrictModes no
Subsystem sftp internal-sftp
ForceCommand internal-sftp -d $FIXTURE/remote
EOF
```

If `2222` is busy, pick another loopback port above 1024 and use that as `PORT` everywhere below. Start a non-root `sshd` with `-f "$FIXTURE/ssh/sshd_config"`. Confirm with:

```bash
sftp -o StrictHostKeyChecking=no -o UserKnownHostsFile="$FIXTURE/ssh/known" \
  -i "$FIXTURE/ssh/id" -P "$PORT" "${USER}@127.0.0.1" <<< 'ls'
```

Expect `My Share`, `café`, and `My%20Share` in that listing. `-d` only selects the login directory; it does not make `$FIXTURE/remote` the SFTP filesystem root. Folder URIs therefore must contain the fixture's absolute path. This loopback daemon is disposable but not chrooted, so authenticate only with the generated key and stop it immediately after testing. If OpenSSH cannot be used, a throwaway SMB share whose names match the same three folders is an allowed substitute; keep URIs `smb://…` and record the protocol in Actual.

Define encoded folder URIs from the absolute fixture path:

```bash
quote_uri_path() {
  python3 -c 'import sys, urllib.parse; print(urllib.parse.quote(sys.argv[1]))' "$1"
}
REMOTE_URI="sftp://127.0.0.1:$PORT$(quote_uri_path "$FIXTURE/remote")"
SPACE_URI="$REMOTE_URI/$(quote_uri_path 'My Share')"
CAFE_URI="$REMOTE_URI/$(quote_uri_path 'café')"
PERCENT_URI="$REMOTE_URI/$(quote_uri_path 'My%20Share')"
SERVER_ROOT_URI="sftp://127.0.0.1:$PORT/"
```

`REMOTE_URI` is the fixture directory, while `SERVER_ROOT_URI` is the actual server filesystem root used only by TP-16.

Unmount leftover GVfs mounts from earlier attempts before starting Strata:

```bash
gio mount -l
# gio mount -u 'sftp://…' for any leftover fixture URI (no passwords in the URI)
```

### 3. Launch Strata from this PR

Build and run the current PR head, recording `git rev-parse HEAD` first, with isolated XDG dirs so GTK bookmarks and preferences do not touch the usual session files:

```bash
export XDG_CONFIG_HOME="$FIXTURE/config"
export XDG_CACHE_HOME="$FIXTURE/cache"
export XDG_DATA_HOME="$FIXTURE/data"
# run the PR binary from the checkout; keep the isolated XDG vars
```

Use a private desktop session, not a shared login. GVfs will prompt for SFTP if key auth is not picked up; complete the prompt with the throwaway key or a throwaway test account. Never type a real password into the location bar (`sftp://user:password@host` is out of scope).

### 4. Open a remote folder

1. `Ctrl+L` (Edit the location).
2. Enter the value of `$REMOTE_URI` (or the SMB fixture URI if that fixture was used).
3. Confirm the mount, then open `My Share`.

GVfs encodes the space as `%20` in the URI. That encoding is what this bug used to show in headings.

### 5. Cleanup (after the last case)

Unmount the fixture URI (`gio mount -u`), stop the throwaway `sshd`, restore any session bookmarks you moved, and `rm -rf "$FIXTURE"`. Do not delete other users’ mounts or `~/.config/gtk-3.0/bookmarks` unless you isolated XDG as above.

## Cases

### TP-01 — Committed unit regression

**Purpose:** Confirm the PR’s regression test still fails the old contract (`My%20Share`) and passes on this head, without a live mount.

**Fixture:** The current PR checkout. Record `git rev-parse HEAD` with the result. No share required.

**Steps:**

1. From the checkout: `./scripts/test-headless.py uri_display_names_are_percent_decoded`
2. Confirm the filter selects `model::tests::uri_display_names_are_percent_decoded` (nonzero).

**Expected:** The test passes. It asserts that encoded `My Share` and `café` folder URIs produce decoded names, while `sftp://host/` falls back to `host`.

### TP-02 — Column heading: space in a remote name

**Purpose:** Primary #658 repro. Columns heading uses `Location::display_name()`.

**Fixture:** Shared SFTP/SMB fixture. Navigate into `My Share`.

**Steps:**

1. `Ctrl+1` for Columns.
2. Open `$REMOTE_URI`, then `My Share`.
3. Read the heading of the column whose location is that folder.
4. Hover the heading.

**Expected:** The heading text is `My Share`, not `My%20Share`. The heading tooltip is the URI/`display_path` and still contains `%20` (for example `…/My%20Share`). The location bar (`Ctrl+L`) also still shows `%20` in the URI.

### TP-03 — Column heading: UTF-8 remote name

**Purpose:** Same helper for `café` and its percent-encoded URI form, as in the issue and unit test.

**Fixture:** Shared fixture. Navigate into `café`.

**Steps:**

1. Stay in Columns.
2. Open `café` from `$REMOTE_URI`.
3. Read the column heading.

**Expected:** Heading is `café`, not its percent-encoded URI form. Tooltip/location bar may show either the UTF-8 path or `%C3%A9` depending on GLib URI display; that path string is `display_path`, not this fix. The **heading label** must be `café`.

### TP-04 — Trailing slash versus none

**Purpose:** GIO basename should match with or without a trailing slash (the unit test covers the encoded `café` URI with a trailing slash).

**Fixture:** Shared fixture, still on `café`.

**Steps:**

1. `Ctrl+L`, submit `$CAFE_URI/` (trailing slash).
2. Read the heading.
3. `Ctrl+L`, submit `$CAFE_URI` without the trailing slash.
4. Read the heading again.

**Expected:** Heading is `café` both times. No crash, no empty heading.

### TP-05 — Breadcrumbs of nested encoded segments

**Purpose:** Each breadcrumb is `crumb.display_name()`. Nested `My%20Share/Sub%20Dir` should decode every segment, not only the leaf.

**Fixture:** Shared fixture. Navigate to `My Share/Sub Dir`.

**Steps:**

1. In Columns, open `My Share`, then `Sub Dir`.
2. Read the breadcrumb trail (not the location-bar URI).
3. Click the `My Share` crumb and confirm that column heading.

**Expected:** Crumbs show decoded names such as `My Share` and `Sub Dir`, not `My%20Share` / `Sub%20Dir`. Host/share labels that were never encoded stay as-is. Clicking a crumb does not re-encode the heading.

### TP-06 — Icons view pane title

**Purpose:** Icons pane title is `snapshot.location.display_name()`.

**Fixture:** Shared fixture. Location = `My Share`.

**Steps:**

1. `Ctrl+2` (Icons).
2. Read the pane header title (the text next to the header actions, not an icon filename).

**Expected:** Title is `My Share`, not `My%20Share`.

### TP-07 — List view pane title

**Purpose:** List pane title uses the same helper.

**Fixture:** Shared fixture. Location = `My Share`.

**Steps:**

1. `Ctrl+3` (List).
2. Read the pane header title.

**Expected:** Title is `My Share`, not `My%20Share`.

### TP-08 — Peek heading

**Purpose:** Folder peek heading is `location.display_name()`.

**Fixture:** Shared fixture. Parent of `My Share` visible in Columns (or Icons).

**Steps:**

1. `Ctrl+1`.
2. Hover the `My Share` row (not click) until peek opens (~180 ms).
3. Read the peek panel heading (accessible name “Folder peek”).
4. Move the pointer away so peek closes.

**Expected:** Peek heading is `My Share`, not `My%20Share`. Rows inside peek may already be decoded via GIO listing; that is pre-existing. This case is the peek **heading**.

### TP-09 — Folder Properties title (current location)

**Purpose:** Empty-pane Properties calls `show_folder_properties` → `location.display_name()`. Distinct from Alt+Enter on a selected row, which uses `FileEntry::display_name`.

**Fixture:** Shared fixture. Location = `My Share`. Nothing required to be selected.

**Steps:**

1. Right-click empty space in the `My Share` pane (not on a file row).
2. Choose Properties.
3. Read the dialog title.
4. Read the LOCATION row.
5. Close the dialog.

**Expected:** Dialog title is `My Share`. LOCATION is the compact `display_path` and still includes `%20` in the URI. No panic.

### TP-10 — Transfer conflict uses the decoded source name

**Purpose:** Copy/move collision dialogs use `source.display_name()`.

**Fixture:** Shared fixture. Remote `My Share` exists. Local `$FIXTURE/dest` already contains a folder named `My Share`.

**Steps:**

1. In Strata, open `$REMOTE_URI` so `My Share` is a row.
2. Copy `My Share` (`Ctrl+C`).
3. Navigate to `$FIXTURE/dest` (native).
4. Paste (`Ctrl+V`).
5. Read the replace/skip dialog copy.
6. Choose Skip (do not replace).

**Expected:** The dialog names the item `My Share` (curly quotes around it), not `My%20Share`. Skip leaves `$FIXTURE/dest/My Share` untouched.

### TP-11 — Pin from folder Properties (label from `display_name`)

**Purpose:** Pinning the current folder passes the Properties title string into GTK bookmarks.

**Fixture:** Isolated `XDG_CONFIG_HOME`. Location = `My Share`.

**Steps:**

1. Open folder Properties for `My Share` (TP-09).
2. Click Pin. Close the dialog.
3. Read the sidebar pinned row label.
4. Unpin from the sidebar so later cases stay clean.

**Expected:** Sidebar label is `My Share`, not `My%20Share`. Unpin removes the row.

### TP-12 — Pinned-place fallback when the bookmark has no label

**Purpose:** `parse_pinned_places` uses `location.display_name()` when a GTK bookmark line has a URI and no label. This is the “name fallback” called out on the issue/PR.

**Fixture:** Isolated `XDG_CONFIG_HOME`. No live mount required for the **label**. Use the same absolute-path URI Strata showed in the location bar for `My Share`, or `$SPACE_URI`, with no trailing label.

**Steps:**

1. Quit Strata.
2. Write a single-line bookmarks file at `$XDG_CONFIG_HOME/gtk-3.0/bookmarks` containing only the URI, no space/label after it. Do not include passwords.
3. Start Strata again with the same isolated XDG vars.
4. Read the pinned row label in the sidebar.
5. Quit and delete that bookmarks file (or overwrite with empty).

**Expected:** The pinned label is `My Share`, not `My%20Share`. Clicking the pin may fail to mount if SFTP is down; that does not fail this case. This case is the **label**.

### TP-13 — Listing rows stay decoded (pre-existing GIO names)

**Purpose:** Directory rows already used GIO `standard::display-name`. This PR must not regress that, and the heading should now match the row.

**Fixture:** Shared fixture. Parent of `My Share` visible.

**Steps:**

1. Open `$REMOTE_URI` in Columns.
2. Read the `My Share` **row** label.
3. Open that folder and compare the **heading**.

**Expected:** Row and heading are both `My Share`. They match. The row was already correct on main; the heading is the fix.

### TP-14 — Native `%20` stays literal

**Purpose:** Native `display_name` is unchanged. A local folder actually named `My%20Share` must not become `My Share`.

**Fixture:** `$FIXTURE/native/My%20Share` only. No SFTP.

**Steps:**

1. `Ctrl+L`, enter the native path to `$FIXTURE/native` (not a `file://` URI).
2. Open `My%20Share`.
3. Read the column or Icons/List heading and the breadcrumb.

**Expected:** Heading and crumb are `My%20Share`, not `My Share`. Location bar shows the native path with `%20` as ordinary characters.

### TP-15 — Remote folder whose real name is `My%20Share` (one-pass decode)

**Purpose:** One-pass decode only. URI `…/My%2520Share` should display `My%20Share`, not `My Share`.

**Fixture:** Shared fixture folder `$FIXTURE/remote/My%20Share`.

**Steps:**

1. From `$REMOTE_URI`, open the folder whose name is literally `My%20Share` (equivalent to opening `$PERCENT_URI`).
2. Read the heading.
3. `Ctrl+L` and confirm the URI encodes the percent as `%2520`.

**Expected:** Heading is `My%20Share`. It is not further decoded to `My Share`. Location bar URI contains `%2520`.

### TP-16 — SFTP root fallback

**Purpose:** When GIO basename is `/`, `file_name()` is `None` and the last URI segment is used (`sftp://host/` → `host` in the unit test).

**Fixture:** Shared SFTP daemon. Unlike every fixture-folder case, navigate to the true server filesystem root, not `$REMOTE_URI` or one of its folders.

**Steps:**

1. `Ctrl+L`, submit `$SERVER_ROOT_URI` (trailing slash).
2. Read the Columns/Icons/List heading.
3. Repeat without the trailing slash if the mount still succeeds.

**Expected:** Heading is the host (and port if GIO keeps it), for example `127.0.0.1` or `127.0.0.1:PORT` — not empty, not `/`, and not a percent-encoded path. Matches the idea of the unit test’s `sftp://host/` → `host`.

### TP-17 — Trash heading is still `Trash`

**Purpose:** `trash:///` remains a special case and must not start using a raw URI segment.

**Fixture:** Isolated XDG. No remote mount.

**Steps:**

1. Open Trash from the sidebar (or `Ctrl+L` → `trash:///`).
2. Read the heading in Columns, then Icons, then List.

**Expected:** Heading is `Trash` in all three views. Location bar remains `trash:///`.

### TP-18 — Second window

**Purpose:** A second window rebuilds headings from the same `display_name()`; no window-local copy of the old split.

**Fixture:** Shared fixture still mounted. First window already showing `My Share` (TP-02).

**Steps:**

1. Open a second Strata window in the same isolated session.
2. Navigate that window to the same `My Share` URI (`Ctrl+L` or the pin).
3. Compare headings in both windows (Columns).

**Expected:** Both headings are `My Share`. Neither shows `My%20Share`.

### TP-19 — Accessibility pane name

**Purpose:** `describe_pane` / `describe_entry_container` pass `location.display_name()` as the accessible label.

**Fixture:** Shared fixture. Location = `My Share`. Accerciser, Accerciser-equivalent, or `accerciser`/`python3-gi` AT-SPI inspector. If AT-SPI is unavailable, mark **BLOCKED**.

**Steps:**

1. Focus the Columns (or Icons/List) pane for `My Share`.
2. Inspect the pane’s accessible name (not the application window title, which stays `Strata`).

**Expected:** Accessible name is `My Share`, not `My%20Share`. Description remains the view name (`Columns` / `Icons` / `List`) or `Files` for the entry list.
